# 会议室预约系统

这是原会议室预约系统的等功能重制版。业务功能保持 1:1，不增加审批、通知、统计、导出、注册或其他流程。

## 功能范围

- 登录与退出
- 单日会议室预约日历
- 新建预约和冲突检查
- 我的预约与取消
- 管理员预约管理
- 管理员用户管理
- 管理员会议室管理

## V1.0.2 预约体验规则

- 过去日期及已经开始的时段不能再创建预约，服务端会在写入前再次确认开始时间。
- 今天的日历会标出当前半小时，并自动定位到当前工作时段附近。
- 当前半小时的空闲格显示“已开始”，更早的空闲格显示“已过期”；已有历史预约仍保留并显示。
- 预约表单会禁用无效的开始/结束时间组合。
- 成功和普通信息提示会自动消失，错误及警告提示保持可见。
- 局域网访问网址发生变化时，仅管理员看到持续提醒；复制新网址并确认已通知同事后，提醒才会关闭。
- 启动器会核对本安装的固定身份，不会把占用同一端口的另一套预约系统当成当前系统打开。

本版本不修改数据库结构，`SCHEMA_VERSION` 继续保持为 `1`。

## 开发运行

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python server.py
```

默认访问地址为 `http://127.0.0.1:8080`。

首次启动会创建管理员 `admin`，随机初始密码保存在
`data/首次登录账号密码.txt`。首次登录后应立即修改密码。

## 数据

- 正式数据库：`data/reservation.db`
- 固定会话密钥：`data/.secret_key`
- 安装身份：`data/install_id`
- 局域网网址状态：`data/局域网访问地址状态.json`
- 备份目录：`backups/`
- 日志目录：`logs/`

不要把 SQLite 数据库放到 NAS、SMB 或其他共享文件系统。
`install_id`、会话密钥和局域网网址状态都属于本安装的运行数据，不应复制到
另一套正在使用的安装中，也不会进入升级负载。

这是全新安装版。不要用旧项目的 `reservation.db` 直接覆盖新版数据库；
如需保留旧数据，应先由维护人员完成数据迁移。

## 版本与数据库迁移

- 当前程序版本读取 `版本.txt`。
- 数据库结构版本由 `app.py` 中的 `SCHEMA_VERSION` 管理，并记录在
  `app_meta.schema_version`。
- 新增结构迁移时必须按版本连续追加到 `MIGRATIONS`，不能修改已经发布的旧迁移。
- 手动检查可运行 `python migrate_check.py --precheck data/reservation.db`；执行当前版本
  迁移与完整性检查可运行 `python migrate_check.py --migrate`。
- `GET /healthz` 供本机启动器和升级器核对安装身份；升级器设置
  `MEETING_ROOM_UPGRADE_CHECK=1` 时，服务只绑定 `127.0.0.1`，不会在版本提交前向局域网开放。

Windows 一键升级包由相邻 `升级包工具/准备发布.py` 从本目录自动组装；制作与验收步骤见
`升级包工具/README-出包说明.txt`。不要手工复制本目录到升级负载或候选部署目录。
