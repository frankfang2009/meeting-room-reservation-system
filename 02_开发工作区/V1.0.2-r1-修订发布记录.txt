会议室预约系统 V1.0.2-r1 修订发布记录
======================================

修订日期
--------

2026-07-26


修订性质
--------

V1.0.2-r1 不改变业务版本、数据库结构或 V1.0.2 功能内容，只替换客户升级入口和
恢复事务。原 V1.0.2 BAT 与清单保持冻结，继续作为故障证据。


根因
----

原 V1.0.2 入口通过 ShellExecute/RunAs 给 BAT 传递 broker 参数。客户重复下载后的
文件名含“(1)”，命中 cmd.exe 的特殊引号解析路径，管理员子进程在主升级逻辑开始前
退出 1，因此没有主升级日志。原 GitHub 测试在管理员 runner 中直接调用 BAT，
没有执行真实入口和 UAC 路径。


修订方案
--------

- 完整 ZIP 交付，零参数 BAT 只启动包内冻结 Python。
- Python 用 ShellExecuteExW 直接提权 python.exe，安装路径只放在 URL-safe Base64
  上下文中；不 RunAs BAT，不经过带参数 cmd /c，不使用 broker。
- 包内固定携带冻结 V1.0.1 受管基线、冻结 V1.0.2 完整目标和冻结 runtime。
- 当前真实 data 只读保护；完整复制后，所有数据库与服务检查均在副本上进行。
- 每次先实际恢复并验证 V1.0.1，再覆盖并验证 V1.0.2，最后提交版本文件。
- 目标提交前失败时严格停在 V1.0.1；提交交接窗口和提交后阶段绝不降级。
- 旧 `_升级回滚` 不用于覆盖当前 data，继续原样保留。
- 新旧两个升级锁全程互斥；旧状态中的原计划任务配置优先恢复。
- 成功后由用户双击“① 启动系统.bat”，更新器不替用户猜测启动身份。
