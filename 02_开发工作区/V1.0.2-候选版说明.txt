会议室预约系统 V1.0.2 候选版说明
================================

状态
----

V1.0.2 是尚未外发的候选版，本轮补丁直接并入同一版本，不额外提高版本号。
数据库结构版本仍为 1，不需要手工迁移。

每次重新生成 V1.0.2 后，旧候选 BAT、旧清单和旧 SHA-256 立即作废。有效文件
及校验值只以“输出-待实机验收”中同一次生成的 BAT 与发布清单为准。

本候选只有同时通过本地自动测试、GitHub Windows PowerShell 5.1 自动化验证和
真实 Windows 10/11 实机人工验收后，才能建立正式归档并发送；此前不得外发。


用户可感知改进
--------------

- 当前半小时的空闲时段显示“已开始”，更早时段显示“已过期”，不能再误点预约。
- 今日页面标出“现在”并定位到当前工作时间附近，手机端优先保证当前行可见。
- 日期增加中文星期。
- 预约表单会自动排除无效时间；改变开始时间时，结束时间默认顺延 30 分钟。
- 成功和普通信息提示会自动收起，错误与警告继续保持可见。
- 静态资源带内容指纹，升级后浏览器不会继续使用旧样式或旧脚本。
- 预约结束时刻一到，前台与后台统一显示为“已完成”。
- 局域网地址变化后，仅管理员看到持续提醒，可对照旧、新地址并复制新地址；
  确认已经通知同事后提醒才消失。
- 同事改用新地址后可能需要重新登录一次，但账号、会议室和预约数据不会变化。


双击升级后的体验
----------------

- 使用者只需先保存当前操作，再双击正式累计升级 BAT 并同意 Windows 管理员授权。
- 双击后会先明确提示正在请求管理员授权；入口代理不再塞在一条超长命令中，
  PowerShell、UAC 或单位安全策略导致的异常也不会直接静默关窗。
- 管理员窗口无法打开时会显示错误代码，并把入口诊断写入
  %TEMP%\meetingroom_upgrade_launcher.log，便于网管判断是否被安全策略拦截。
- 升级器自动定位、备份、更新、检查并恢复原运行状态，不需要复制 reservation.db、
  手工迁移数据或修改配置。
- 升级会有短暂停机；停机瞬间正在提交的页面可能需要在成功后刷新并重试。
- 成功摘要说明当前版本、数据保留结果、系统已恢复运行或保持停止，以及局域网
  地址未变、已变化或暂时无法确认。
- 同一电脑发现多套有效安装时不会猜目录，必须由操作者明确选择。
- 正式安装只支持本机固定磁盘，不支持共享盘、U 盘、移动硬盘和网盘同步目录。


升级安全补强
------------

- 每套安装保存独立安装身份；健康检查不会把占用 8080 的其他程序或另一套安装
  误判为本系统。
- 升级事务期间暂时禁用属于本安装的开机任务；成功或回滚后恢复原配置和原
  运行状态，强杀、断电或重启时不会自动暴露半升级程序。
- 版本提交前只通过回环地址做维护检查，不向同事开放可能被回滚的新版服务。
- 版本已经持久提交后，即使真实服务恢复失败，也只保留新程序、新数据和恢复
  状态，不会回滚已经提交后的新预约。
- 成功事务删除完整数据回滚快照；失败或未完成事务继续保留恢复及诊断证据。
- 地址状态写入失败只给出警告，不阻断系统，也不会把有效旧地址替换成无效地址。


候选交付物
----------

1. 单文件累计升级包：
   升级包工具\输出-待实机验收\升级到V1.0.2.bat

2. 可机器核验的发布清单：
   升级包工具\输出-待实机验收\V1.0.2-发布清单.json

3. 本地完整部署候选：
   发布暂存\V1.0.2\Windows部署目录-V1.0.2-待实机验收

4. 后续小版本统一入口：
   升级包工具\准备发布.py

SHA-256 用于发现传输损坏或误编辑，不是数字签名。BAT 和发布清单必须成对交付，
不得沿用本轮补丁前的候选哈希。


自动化验证门槛
--------------

- 业务、权限、并发、时间边界、备份、地址状态、管理员提醒和数据库迁移测试。
- 出包、路径安全、敏感文件排除、冻结 runtime、反向解包、成对原子交付和发布
  组装测试。
- V1.0.0 → V1.0.2、V1.0.1 → V1.0.2 的成功升级及重复运行。
- 两种旧版本起点的故障回滚，以及 version_committed 后新增数据保护。
- 原运行/停止状态、计划任务存在/启用/运行状态的组合恢复。
- 每个事务阶段强杀或模拟重启，确认提交前无局域网写入窗口、提交后不回滚新数据。
- 多安装选择、错误任务路径、runtime 篡改、端口冲突和安装身份核对。
- 地址未变、变化、连续变化、历史日志建基线、状态损坏及写入失败。
- 成功快照清理、失败证据保留，以及最终 BAT、清单、源码和累计负载逐文件一致。


Windows 实机门槛
----------------

GitHub Actions 必须对最终候选所在的准确提交直接运行并通过。自动化通过后，仍须按
“升级机制实施计划.md”和完整候选中的网管清单，在真实 Windows 10/11 上验收：

- UAC、SmartScreen、杀毒软件/EDR、AppLocker 和单位组策略；
- 真实计划任务、文件占用、并发双击、强杀、重启和物理断电恢复；
- Windows 防火墙、VPN、DHCP、网卡切换及固定局域网 IP；
- 服务器本机与另一台同事电脑的真实访问，地址变化后的复制通知和重新登录。

回环健康检查不能证明同事电脑一定可访问，因此真实局域网验收不能省略。

V1.0.0 正式归档和 V1.0.1 候选基线继续保持只读。
