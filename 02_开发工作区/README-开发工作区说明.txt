开发工作区说明
==============

源代码工作区
------------

这是程序文件的唯一修改来源。用于后续修复和开发新版本。
升级负载和候选部署必须由“升级包工具”中的对应版本生成器自动生成，禁止手工同步程序文件。
V1.0.3 及后续正式更新候选优先使用“制作正式更新包.py”生成完整更新 ZIP；
“准备发布.py”和旧单文件累计 BAT 只保留历史兼容与回归用途，不再作为当前客户入口。

注意：“源代码工作区\data”是 Mac 本机试玩产生的数据，包含本机管理员密码和会话密钥，禁止打包或发送给客户。


Windows部署目录-V1.0.0
----------------------

这是当前 Windows 交付包的解压参考目录，用于对照和制作后续升级包。
真正已经发给客户的原始 ZIP 保存在“01_版本归档”中。


Windows部署目录-V1.0.1-待实机验收
--------------------------------

这是已经组装好的 V1.0.1 完整部署候选目录。Mac 自动测试及 GitHub Windows PowerShell 5.1
的成功升级、重复运行和故障回滚均已通过；UAC、SmartScreen、计划任务和真实局域网访问
仍须在 Windows 10/11 实机人工验收。
验收前不要把它当成正式客户版本，也不要放入“01_版本归档”。
后续版本不得修改这里；它是 V1.0.2 跨版本升级与回滚测试的冻结基线。


发布暂存
--------

这里保存版本生成器从唯一源码生成的版本化负载、升级包、完整 Windows 候选和发布清单。
V1.0.3 由“制作正式更新包.py”生成版本化完整更新 ZIP 和候选清单。
整个目录是可重新生成的本机暂存，不作为新的源码来源，也不会进入 Git。


升级包工具
----------

这里包含稳定发布骨架、一键发布组装器、单文件升级包生成器、PowerShell 事务逻辑和测试。
V1.0.1 候选成品保持冻结；V1.0.2-r1 修复通道和原 V1.0.2 故障入口保持为历史证据。
当前 V1.0.3 候选由“制作正式更新包.py”生成到“发布暂存\V1.0.3-candidate”。


后续版本路线图
--------------

“后续版本路线图-V1.0.4至V1.1.x.md”记录修改预约、只读 API、大屏、提醒、
结构整理及 V1.1 产品转型的讨论结论。它是规划基线，不是当前候选范围、正式发布记录
或外发承诺。


开发原则
--------

- V1.0.0 归档只读保存。
- 程序修改只在“源代码工作区”进行。
- 发布新版本时重新生成干净 ZIP，不能包含 data、logs、backups、缓存或本机密码。
- V1.0.3 只有完成自动化和 Windows 10/11 普通用户实机人工验收后，才可建立正式
  发布记录、归档和发送给客户。
