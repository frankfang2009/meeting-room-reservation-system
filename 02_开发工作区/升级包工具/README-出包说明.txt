会议室预约系统——升级包制作与验收说明
========================================

当前开发候选：V1.0.3
--------------------

V1.0.3 不再使用后文保留的“累计单 BAT + PowerShell + 带参数 RunAs BAT”作为
客户更新入口。候选包必须在本目录运行：

  python3 制作正式更新包.py

如在干净 worktree 开发、冻结 runtime 位于另一只读目录，可显式指定：

  python3 制作正式更新包.py --runtime-source "完整的冻结runtime路径"

指定目录仍必须通过固定 runtime 树哈希，不能借此更换依赖或运行环境。输出固定为：

  02_开发工作区\发布暂存\V1.0.3-candidate\
  ├─ 会议室预约系统-V1.0.3-候选更新.zip
  └─ V1.0.3-候选更新清单.json

候选 ZIP 顶层只有零参数“更新到V1.0.3-候选版.bat”和说明；BAT 只启动包内
Python，校验、定位和 Windows runas 均由 Python 完成。包内同时携带：

1. 冻结 V1.0.2 完整安全基线；
2. 从唯一源码与发布骨架组装的 V1.0.3 完整目标；
3. 冻结且哈希固定的 runtime；
4. 只用于收敛未完成 r1 事务的冻结 V1.0.2-r1 引擎与 V1.0.1 恢复负载。

必须验证实际缺少 版本.txt 的 V1.0.0、V1.0.1、干净 V1.0.2、r1 修复后状态、
r1 未完成事务、旧累计升级残留、重复运行和目标失败回退。目标检查失败时程序收敛
到逐文件验证的 V1.0.2 安全基线；任何路径都不得覆盖 data、密钥、安装身份、地址
状态或未知客户文件。

当前清单必须保持 status=windows_acceptance_candidate_only 和
formal_external_release_allowed=false。GitHub hosted runner 已处于管理员上下文，
其全绿结果不能替代普通用户 Explorer 双击、UAC 安全桌面、SmartScreen、EDR、
计划任务、启动和真实同事电脑局域网访问。上述实机验收完成前不得正式外发。

当前特别说明：V1.0.2-r1
------------------------

本文件后续章节保留原“累计单 BAT + PowerShell”通道的历史约束，供 V1.0.3 以后评估。
客户当前 V1.0.2 故障修复不得重新生成或发送旧单 BAT，必须使用独立修复通道：

  python3 制作覆盖更新包.py

输出固定为：

  02_开发工作区\发布暂存\V1.0.2-r1\
  ├─ 会议室预约系统-V1.0.2-修复更新-r1.zip
  └─ V1.0.2-r1-发布清单.json

生成器会把以下三份冻结输入组装到同一个 ZIP，并反向调用成品中的 Bundle.load 验收：

1. SHA 固定的 V1.0.1 完整受管 Payload；
2. SHA 固定的 V1.0.2 完整受管 Payload；
3. V1.0.1 Windows 候选中 SHA 固定的完整 runtime。

修复入口是零参数 BAT；提权目标是包内 python.exe，不是 BAT。客户真实 data 不进入
Payload，也不会被修复器写回。修复器实际写入并验证 V1.0.1 基线后再写 V1.0.2，
最后才提交版本文件。

旧“输出-待实机验收\升级到V1.0.2.bat”和配套清单是只读故障证据。修复出包目标
已存在时生成器会拒绝覆盖；需要重出候选时，必须先明确归档或移走旧 V1.0.2-r1 目录。

V1.0.2-r1 发布门槛：

- 全部业务测试和升级包工具测试通过；
- 新 ZIP 可重复构建且字节一致；
- Windows runner 的特殊路径、BAT、任务、残留和 data 全树测试通过；
- Windows 10/11 普通用户真实双击 UAC/SmartScreen/EDR 验收通过；
- 另一台同事电脑可访问并完成登录、查询和新建预约。

一、先确认这些前提

1. 升级包必须是“完整累计包”，不能只放本次改动的文件。任何受支持的旧版本都应能直接升级到目标版本。
2. 本期不升级 _程序文件\runtime，也不允许新增或改变 Python 依赖。requirements.txt 必须保持：
   Flask>=3.0,<4
   waitress>=3.0,<4
   完整候选使用的 runtime 还必须通过冻结目录哈希校验；任何漂移都会拒绝组装。
3. 不得从客户安装目录复制 data、backups、logs 或 runtime 到负载中。
4. V1.0.0 归档只读，禁止修改。新版本另建归档目录。
5. 客户侧必须已有 _程序文件\data\reservation.db。本升级通道用于已经初始化并投入使用的安装；尚未首次启动、还没有数据库的部署，应先正常启动一次完成初始化，再运行升级包。
6. 生成器会产生字节级可重复的 ZIP/BAT，但“字节完全相同”只保证在同一 Python 和 zlib 版本、相同输入下成立。
7. 生成器依赖当前“02_开发工作区”相对目录布局读取 V1.0.0 冻结 requirements；不要只把“升级包工具”目录单独复制到别处出包。
8. 正式安装目录必须位于本机固定磁盘；共享盘、U 盘、移动硬盘和网盘同步目录不属于支持范围。升级器定位到多个有效安装时不得按盘符顺序猜测，必须让操作者明确选择。

二、每次发版的标准流程

1. 在“源代码工作区”修改代码。涉及数据库结构时，只追加迁移，并同步提高 SCHEMA_VERSION；不要改写或删除旧迁移。
   第一次加入真实迁移及以后每次新增迁移时，都要增加端到端测试：复制一份 V1.0.0 形态数据库，运行 init_db()，断言升级到目标结构版本且原业务数据不变。
2. 更新“源代码工作区\版本.txt”。文件必须是 UTF-8 无 BOM、LF 结尾，内容只能是 X.Y.Z。
3. 运行全部业务测试、迁移测试和升级包生成器测试，确认全部通过。
4. 不要手工同步“负载示例”或历史 Windows 候选目录。在升级包工具目录运行：

   python3 准备发布.py --package-out "输出-待实机验收/升级到VX.Y.Z.bat" --manifest-out "输出-待实机验收/VX.Y.Z-发布清单.json"

   工具会严格从“源代码工作区”和“发布骨架”组装版本化“发布暂存”，自动排除 tests、
   data、logs、backups、runtime、缓存、密码和其他白名单外文件；再从同一负载生成升级
   BAT、完整 Windows 候选目录和发布清单。static/templates 中出现敏感路径或未知文件
   类型时会直接失败。目标版本暂存已存在时会拒绝覆盖；外部 BAT 和清单任一交付失败时，
   两者都会恢复原状。

5. `制作升级包.py <完整负载目录> <X.Y.Z>` 仍保留给生成器开发、故障包测试和 CI 使用；
   正常发版必须通过“准备发布.py”，避免绕过唯一源码检查。

6. 保存自动生成的发布清单。它记录程序源码树、逐文件哈希、ZIP SHA-256、BAT SHA-256、
   数据库结构版本和支持的旧版本。SHA-256 只用于发现损坏或误编辑，不是数字签名。
7. 在干净的 Windows 10/11 测试副本上真实双击 BAT。Mac 与 GitHub Windows 自动化验证
   均不能替代 UAC、SmartScreen、杀毒软件/EDR、AppLocker、计划任务、防火墙、VPN、
   DHCP 和真实同事电脑访问的实机人工验收。
8. 验收通过后，同时制作新的完整部署 ZIP 和单文件升级 BAT，并建立对应版本归档；不要覆盖旧归档。

三、Windows 发版前最低验收

至少完成以下检查，并保存最新的 _程序文件\logs\upgrade-*.log：

1. 从 V1.0.0 测试副本直接升级成功，账号、会议室、预约、会话密钥和首次登录信息均保留。
2. 从最近一个候选/正式版本测试副本升级成功；故障回滚后旧版本文件和完整程序树必须恢复。
3. 再运行同一 BAT，提示“无需升级”，退出码为 0。
4. 缺少版本.txt 的 V1.0.0 可升级；非法版本文件安全停止。
5. 分别制造程序语法错误、迁移失败和服务启动失败，均不能显示成功；程序树和数据库必须自动恢复。
6. 计划任务存在且原来运行、计划任务存在但原来停止、无计划任务且手动运行三种状态，升级后都恢复原状态。
7. 原来未运行时，升级器会临时启动新版做健康检查，检查后必须再次停止。
8. 连续双击两次，第二个窗口只提示“升级正在进行”。
9. 测试 UAC 取消、选目录取消、空间不足和文件占用，确认不会留下半升级状态。
   另需从普通用户桌面真实双击一次，确认先显示“正在请求 Windows 管理员授权”，
   UAC 前后的窗口均不会静默关闭；入口失败时应显示错误代码，并在
   %TEMP%\meetingroom_upgrade_launcher.log 留下诊断记录。
10. 分别在程序覆盖后、迁移后、健康检查后终止升级进程；下次运行应先恢复旧程序和旧数据，再重新升级。另在版本文件已提交并写入 version_committed 后终止，加入新的预约数据，再次运行升级包；必须只清理残留状态，绝不能回滚程序或 data。
11. 分别在无计划任务、计划任务已启用、计划任务已禁用，以及原系统运行/停止组合下测试；事务期间任务必须被安全禁用，成功或回滚后恢复原配置和原运行状态。
12. 在每个事务阶段强杀升级进程并模拟重启；版本提交前不得向局域网开放新版服务，提交后的重启失败不得回滚已经提交的新程序和新数据。
13. 制造 8080 端口被其他程序或另一套安装占用的情况；健康检查必须核对安装实例身份，不能把无关服务当成升级成功。
14. 在同一电脑准备两套有效安装；升级器必须要求明确选择，选择取消或错误目录时不得修改任一安装。
15. 模拟局域网地址未变、变化、连续变化和无法确认；成功摘要需显示最终运行状态与地址结果，管理员页面需持续提醒并可复制新地址，普通用户不可见该提醒。
16. 验证成功事务的完整数据回滚快照已清理，失败或未完成事务仍保留恢复及诊断证据。
17. 对照“升级机制实施计划.md”和候选目录中的网管清单完成全部 Windows 人工验收。

四、升级器的安全边界

升级器会在停止系统前完成负载 Base64、SHA-256、ZIP 路径、双重白名单、版本和依赖校验。它只接受本机固定磁盘上的有效安装；只有一个候选时自动选择，多个候选时要求操作者明确选择，不能按搜索顺序猜测。定位后使用独占锁，并核对计划任务的程序路径、工作目录和安装实例身份；发现 _升级状态.json 时先按持久化阶段恢复或收尾，再判断版本。停机前会原子写入事务状态并临时禁用属于该安装的开机任务，因此即使强杀、断电或重启，也不会自动暴露半升级程序。

成品 BAT 自身必须保持 UTF-8 无 BOM + CRLF；BAT 抽取出的临时 PS1 会单独写成带 BOM 的 UTF-8，确保 Windows PowerShell 5.1 能正确读取中文路径和白名单。不要手工改编码或重新保存成品 BAT。

升级前会记录系统是否运行，以及计划任务是否存在、是否启用和是否正在运行；停止的仅是已核对安装目录 runtime 下的 python.exe/pythonw.exe。升级器不会在验证旧 runtime 前以管理员权限执行已安装的旧 server.py。升级器会对完整受管程序和整个 data 建立并验证回滚快照；覆盖时不碰 runtime、backups 或既有 logs。static 和 templates 按累计包精确镜像。覆盖前会重新核对临时 Payload 的逐文件长度和 SHA-256，覆盖后会再次核对安装目录受管文件的精确集合、长度和 SHA-256。

_程序文件\__pycache__ 是可丢弃的运行缓存，不进入 Payload 或回滚快照。升级器会在运行新代码前及回滚旧代码后精确清理这个根层缓存，避免 Python 误用跨版本的旧 .pyc；其他目录不按此规则清理。

升级 BAT 可以放在桌面、下载目录或安装目录根层，但不能改名占用“① 启动系统.bat”等受管文件名，也不能放进“_程序文件”内部；否则升级器会在停机前拒绝执行。

迁移和自检通过后，新版只允许通过回环地址做维护健康检查，不向同事开放写入窗口。版本.txt 与“已提交”状态持久化以后，才恢复真实服务和计划任务。版本一旦提交，后续启动或清理失败只能保留新程序、新数据和可恢复状态，绝不能恢复旧程序或旧 data；提交前失败时统一恢复旧程序、旧 data、计划任务和原运行状态。持久成功后删除该事务的完整数据回滚快照；失败或未完成事务的恢复与诊断证据继续保留。

每套安装在 data 中保存自己的安装身份和局域网地址状态；这些运行数据不进入升级负载。健康检查除了版本外还必须核对安装身份，避免把占用 8080 的其他程序误判为本系统。首次升级会尽量从历史 server.log 建立原地址基线；地址未变不打扰，地址变化后由管理员页面持续显示旧、新地址并提供复制，确认已经通知同事后才消失。状态文件损坏或暂时无法写入只能给出警告，不得阻断系统或回滚已经成功的升级。

退出码：
0  升级成功，或当前版本无需升级
1  升级失败，但已自动恢复；或在修改前安全停止
2  用户取消选择安装目录
3  用户取消 UAC
4  另一个升级正在进行
5  自动恢复没有完成，必须停止操作并联系维护人员

BAT、UAC 或入口代理阶段尚未定位到安装目录时，不一定会产生
_程序文件\logs\upgrade-*.log；这类早期故障请查看
%TEMP%\meetingroom_upgrade_launcher.log。入口代理的任何未知退出码都必须在窗口中
显示并暂停，禁止直接关窗。

五、升级会影响什么

1. 会有短暂停机。升级开始前应让同事保存当前操作；停机瞬间正在提交的请求可能失败，升级成功后刷新页面重试即可。
2. 不需要手工迁移。正式累计升级包会自动备份、升级、检查并恢复原运行状态；不得让客户复制 reservation.db、覆盖 data 或手改配置。
3. 账号、会议室、预约、会话密钥和数据目录应保持不变。升级成功摘要必须明确版本、数据保留结果、最终运行状态和地址结果。
4. 局域网地址可能因 DHCP、VPN、网卡或网络策略变化。地址变化不等于数据变化，但旧链接可能失效；同事打开新地址时可能因浏览器站点身份变化而重新登录。
5. UAC、SmartScreen、杀毒软件/EDR、AppLocker 和单位组策略是系统外部边界。未签名 BAT 无法承诺永不弹窗或永不拦截，不得指导客户关闭安全软件；应提供文件名和 SHA-256，由单位网管按规则确认。
6. 回环健康检查只能证明服务器本机可用，不能证明同事电脑能穿过真实防火墙、VPN 和局域网访问。正式外发前必须做物理 Windows 及另一台同事电脑验收。

六、发给客户的文字

请先让正在使用的同事保存当前操作，然后双击“升级到VX.Y.Z.bat”，在 Windows 询问时选择“是”。升级会短暂停止服务，但会自动备份、更新、检查并恢复原运行状态，不需要复制数据库或修改配置。不要在升级期间关机、重启或关闭窗口。

看到“升级成功”后，请核对窗口里的当前版本、数据保留结果、运行状态和“同事访问”地址。如果地址变化，复制新地址发给同事；同事可能需要重新登录一次，原预约数据不会变化。电脑里有多套安装时，升级器会要求明确选择；不确定请选择取消并联系维护人员。

如果出现 SmartScreen、杀毒软件/EDR 或单位组策略提示，不要关闭安全软件。请先核对文件名和维护人员提供的 SHA-256，再由单位网管按本单位规则确认或放行。

只发送客户需要的完整部署 ZIP 或单文件升级 BAT，不发送本工具目录、源代码测试文件或客户数据样本。
