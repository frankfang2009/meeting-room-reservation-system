会议室预约系统——升级包制作与验收说明
========================================

一、先确认这些前提

1. 升级包必须是“完整累计包”，不能只放本次改动的文件。任何受支持的旧版本都应能直接升级到目标版本。
2. 本期不升级 _程序文件\runtime，也不允许新增或改变 Python 依赖。requirements.txt 必须保持：
   Flask>=3.0,<4
   waitress>=3.0,<4
   完整候选使用的 runtime 还必须通过冻结目录哈希校验；任何漂移都会拒绝组装。
3. 不得从客户安装目录复制 data、backups、logs 或 runtime 到负载中。
4. V1.0.0 归档只读，禁止修改。新版本另建归档目录。
5. 客户侧必须已有 _程序文件\data\reservation.db。本升级通道用于已经初始化并投入使用的安装；尚未首次启动、还没有数据库的部署，应先正常启动一次完成初始化，再运行升级包。
6. 生成器会产生字节级可重复的 ZIP/BAT，但“字节完全相同”只保证在同一 Python 和 zlib 版本、相同输入下成立。
7. 生成器依赖当前“02_开发工作区”相对目录布局读取 V1.0.0 冻结 requirements；不要只把“升级包工具”目录单独复制到别处出包。

二、每次发版的标准流程

1. 在“源代码工作区”修改代码。涉及数据库结构时，只追加迁移，并同步提高 SCHEMA_VERSION；不要改写或删除旧迁移。
   第一次加入真实迁移及以后每次新增迁移时，都要增加端到端测试：复制一份 V1.0.0 形态数据库，运行 init_db()，断言升级到目标结构版本且原业务数据不变。
2. 更新“源代码工作区\版本.txt”。文件必须是 UTF-8 无 BOM、LF 结尾，内容只能是 X.Y.Z。
3. 运行全部业务测试、迁移测试和升级包生成器测试，确认全部通过。
4. 不要手工同步“负载示例”或历史 Windows 候选目录。在升级包工具目录运行：

   python3 准备发布.py --package-out "输出-待实机验收/升级到VX.Y.Z.bat" --manifest-out "输出-待实机验收/VX.Y.Z-发布清单.json"

   工具会严格从“源代码工作区”和“发布骨架”组装版本化“发布暂存”，自动排除 tests、
   data、logs、backups、runtime、缓存、密码和其他白名单外文件；再从同一负载生成升级
   BAT、完整 Windows 候选目录和发布清单。static/templates 中出现敏感路径或未知文件
   类型时会直接失败。目标版本暂存已存在时会拒绝覆盖；外部 BAT 和清单任一交付失败时，
   两者都会恢复原状。

5. `制作升级包.py <完整负载目录> <X.Y.Z>` 仍保留给生成器开发、故障包测试和 CI 使用；
   正常发版必须通过“准备发布.py”，避免绕过唯一源码检查。

6. 保存自动生成的发布清单。它记录程序源码树、逐文件哈希、ZIP SHA-256、BAT SHA-256、
   数据库结构版本和支持的旧版本。SHA-256 只用于发现损坏或误编辑，不是数字签名。
7. 在干净的 Windows 10/11 测试副本上真实双击 BAT。Mac 与 GitHub Windows 自动化验证
   均不能替代 UAC、SmartScreen、计划任务和真实局域网环境的实机人工验收。
8. 验收通过后，同时制作新的完整部署 ZIP 和单文件升级 BAT，并建立对应版本归档；不要覆盖旧归档。

三、Windows 发版前最低验收

至少完成以下检查，并保存最新的 _程序文件\logs\upgrade-*.log：

1. 从 V1.0.0 测试副本直接升级成功，账号、会议室、预约、会话密钥和首次登录信息均保留。
2. 从最近一个候选/正式版本测试副本升级成功；故障回滚后旧版本文件和完整程序树必须恢复。
3. 再运行同一 BAT，提示“无需升级”，退出码为 0。
4. 缺少版本.txt 的 V1.0.0 可升级；非法版本文件安全停止。
5. 分别制造程序语法错误、迁移失败和服务启动失败，均不能显示成功；程序树和数据库必须自动恢复。
6. 计划任务存在且原来运行、计划任务存在但原来停止、无计划任务且手动运行三种状态，升级后都恢复原状态。
7. 原来未运行时，升级器会临时启动新版做健康检查，检查后必须再次停止。
8. 连续双击两次，第二个窗口只提示“升级正在进行”。
9. 测试 UAC 取消、选目录取消、空间不足和文件占用，确认不会留下半升级状态。
10. 分别在程序覆盖后、迁移后、健康检查后终止升级进程；下次运行应先恢复旧程序和旧数据，再重新升级。另在版本文件已提交并写入 version_committed 后终止，加入新的预约数据，再次运行升级包；必须只清理残留状态，绝不能回滚程序或 data。
11. 对照“升级机制实施计划.md”完成全部 Windows 人工验收。

四、升级器的安全边界

升级器会在停止系统前完成负载 Base64、SHA-256、ZIP 路径、双重白名单、版本和依赖校验。定位安装目录后使用独占锁；发现 _升级状态.json 时先恢复上次事务，再判断版本。停机前会先原子写入 preparing 状态，因此即使在停机或制作快照时断电，下次也能恢复原运行状态；若回滚中断导致 app.py、server.py 或启动 BAT 暂时缺失，升级器仍可凭 runtime 和状态文件识别并继续恢复。

成品 BAT 自身必须保持 UTF-8 无 BOM + CRLF；BAT 抽取出的临时 PS1 会单独写成带 BOM 的 UTF-8，确保 Windows PowerShell 5.1 能正确读取中文路径和白名单。不要手工改编码或重新保存成品 BAT。

升级前会记录系统是否运行及计划任务是否存在，停止的仅是本安装目录 runtime 下的 python.exe/pythonw.exe。升级器会对完整受管程序和整个 data 建立并验证回滚快照；覆盖时不碰 runtime、backups 或既有 logs。static 和 templates 按累计包精确镜像。覆盖前会重新核对临时 Payload 的逐文件长度和 SHA-256，覆盖后会再次核对安装目录受管文件的精确集合、长度和 SHA-256。

_程序文件\__pycache__ 是可丢弃的运行缓存，不进入 Payload 或回滚快照。升级器会在运行新代码前及回滚旧代码后精确清理这个根层缓存，避免 Python 误用跨版本的旧 .pyc；其他目录不按此规则清理。

升级 BAT 可以放在桌面、下载目录或安装目录根层，但不能改名占用“① 启动系统.bat”等受管文件名，也不能放进“_程序文件”内部；否则升级器会在停机前拒绝执行。

迁移、自检和真实启动健康检查全部通过后，版本.txt 才会通过同卷临时文件原子提交；随后原子写入 version_committed 阶段，再清理状态文件。版本一旦提交，后续清理失败只能保留状态并在下次运行时安全收尾，绝不能恢复旧程序或旧 data。提交前失败时统一恢复旧程序、旧 data 和原运行状态。回滚快照、failed-data 诊断副本和新建的升级日志不会自动删除。

退出码：
0  升级成功，或当前版本无需升级
1  升级失败，但已自动恢复；或在修改前安全停止
2  用户取消选择安装目录
3  用户取消 UAC
4  另一个升级正在进行
5  自动恢复没有完成，必须停止操作并联系维护人员

五、发给客户的文字

请先保存正在进行的工作，然后双击“升级到VX.Y.Z.bat”，在 Windows 询问时选择“是”。看到“升级成功”后即可关闭窗口；如果出现 SmartScreen，请先核对文件名和维护者提供的 SHA-256，再选择“更多信息—仍要运行”。

只发送客户需要的完整部署 ZIP 或单文件升级 BAT，不发送本工具目录、源代码测试文件或客户数据样本。
