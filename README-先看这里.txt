会议室预约系统文件夹说明
========================

当前业务版本：V1.0.2
当前修复更新通道：V1.0.2-r1


一、这次给现有客户发送什么
--------------------------

V1.0.2-r1 完成 Windows 自动化和普通用户 UAC 实机验收后，只发送同一次生成的：

1. 02_开发工作区\发布暂存\V1.0.2-r1\
   会议室预约系统-V1.0.2-修复更新-r1.zip
2. 02_开发工作区\发布暂存\V1.0.2-r1\
   V1.0.2-r1-发布清单.json

旧文件“升级包工具\输出-待实机验收\升级到V1.0.2.bat”已经冻结为历史故障证据，
不得再发给客户，也不得修改或覆盖。


二、客户只需要做什么
--------------------

1. 把完整修复 ZIP 解压出来，不能只拖出其中一个 BAT。
2. 双击“修复并更新到V1.0.2.bat”。
3. Windows 询问管理员权限时选择“是”。
4. 看到完成提示后，回到原系统文件夹双击“① 启动系统.bat”。

设计上保留最后一次“启动”点击：管理员修复进程只负责停机、修复和校验，不替客户
猜测用 SYSTEM 计划任务还是普通用户身份启动服务。这样多一步，但权限边界更清楚。


三、修复更新的安全边界
----------------------

- 先校验冻结的 V1.0.1 完整受管程序、V1.0.2 完整目标和冻结 runtime。
- 取得新旧两个升级锁，保存停机前计划任务配置，再停止属于本安装的服务。
- 把当前真实 data 当作唯一权威源，只复制快照并在副本上做数据库和回环检查。
- 受管程序实际恢复并逐文件校验为 V1.0.1 后，才覆盖 V1.0.2。
- V1.0.2 检查通过前，安装目录中的“版本.txt”始终保持 1.0.1。
- 提交前失败会收敛到冻结 V1.0.1；提交后绝不自动降级。
- 不从旧“_升级回滚”恢复 data；旧回滚证据原样保留。
- reservation.db、.secret_key、install_id、首次登录文件和 data 中未知文件不被覆盖。
- 既有 backups 和 logs 不删除；只新增本次修复日志和一份独立数据库备份。


四、以后在哪里开发和出包
------------------------

唯一业务源码：
02_开发工作区\源代码工作区

V1.0.2-r1 修复更新源码：
02_开发工作区\升级包工具\覆盖更新.py
02_开发工作区\升级包工具\覆盖更新入口.bat
02_开发工作区\升级包工具\制作覆盖更新包.py

出包命令：

python3 02_开发工作区/升级包工具/制作覆盖更新包.py

生成器固定校验历史 V1.0.1/V1.0.2 BAT、V1.0.2 清单和冻结 runtime 的 SHA-256；
“发布暂存\V1.0.2-r1”已存在时拒绝覆盖，必须先明确处理旧候选，不能静默混包。

V1.0.0 正式归档、V1.0.1 冻结候选、原 V1.0.2 BAT 与清单都是只读历史基线。
不要把“02_开发工作区”、源码、测试、客户 data、logs、runtime 或密码文件发给客户。
