# V2.5.0 Windows 全新安装实机验收指南

适用版本：`v2.5.0` 首次安装版

产品标签与候选源码：`32a0bbbdbec26c250f02660db5b7aac37a31239b`

> 本指南只用于专用 Windows 测试机，以合成数据验收 V2.5.0 全新安装。不要导入、读取、
> 修改或删除 V1 数据，不要使用客户数据库、账号、日志、备份或真实个人信息。发现问题时
> 先保存脱敏证据，不要在测试机上修产品代码。即使本指南全部通过，在 Authenticode 签名
> 与目标单位安全软件门禁完成前，Windows 仍保持
> `formal_external_release_allowed=false`。

## 1. 验收目标与硬边界

本轮验证用户第一次安装 V2.5.0 的真实体验，重点覆盖：

- 普通用户双击安装、SmartScreen、UAC 取消与接受；
- 固定 Program Files 安装根、首次设置前仅回环、设置后局域网开放；
- 有一定合成数据时的预约、交接、历史、数据中心、帮助中心、侧栏和空状态体验；
- 标准用户 DACL、计划任务、防火墙、端口冲突、备份恢复与真实重启；
- Windows 10/11 64 位 x86-64（AMD64）、四档视口、显示缩放、
  Defender/EDR/AppLocker/组策略表现。

硬性边界：

1. 只在无客户数据的专用测试机执行。若机器上已经存在 V2 安装或以下同名系统对象，停止
   并报告，不要按旧任务书自动删除：
   - `%ProgramFiles%\会议室预约系统V2`
   - `HKLM\Software\MeetingRoomReservationV2`
   - 计划任务 `会议室预约系统 V2`、`会议室预约系统 V2 每日备份`
   - 防火墙规则 `会议室预约系统V2-手动`、`会议室预约系统V2-后台`
2. 不得关闭 UAC、SmartScreen、Defender、EDR、AppLocker 或防火墙来换取通过。
3. 不执行累计升级包。本指南只验收 V2.5.0 作为第一个安装版本；artifact 中的累计升级包
   保持未使用。
4. 测试机必须是 Windows 10/11 64 位 x86-64（AMD64）；Windows ARM64 或 32 位机器
   属于环境阻断，不得计入通过证据。
5. UAC 接受/取消、SmartScreen 放行、重启和任何证书动作由用户本人操作。
6. 不把候选 ZIP、数据库、备份、日志、secret、原始 transcript 或含真实信息的截图上传
   GitHub。仓库只接收脱敏 Markdown 摘要。

### 2.1 SmartScreen 验收的主下载路径

必须用真实浏览器完成这一段；命令行下载通常不会保存浏览器赋予的 Mark-of-the-Web
（MOTW），因此不能作为 SmartScreen 通过证据。

1. 在普通用户会话的浏览器中打开上述 Actions run，登录 GitHub。
2. 点击 artifact `meeting-room-v2-candidate` 下载。不要使用浏览器或第三方工具的“移除阻止”
   功能，不要先把文件复制到不支持 NTFS Alternate Data Streams 的介质。
3. 在 Windows PowerShell 或 PowerShell 7 中把 `$ArtifactZip` 改为浏览器实际下载的 ZIP；
   `$TestRoot` 改为用户可写的独立目录。优先使用本机 NTFS 非系统盘，没有 D 盘时可使用
   Documents，但不要放进 Program Files。

```powershell
$TestRoot = 'D:\mrv2-v25'
New-Item -ItemType Directory -Force `
  "$TestRoot\artifacts", "$TestRoot\evidence", "$TestRoot\screenshots" | Out-Null

$ArtifactZip = "$env:USERPROFILE\Downloads\meeting-room-v2-candidate.zip"
Get-FileHash -Algorithm SHA256 -LiteralPath $ArtifactZip
Get-Item -LiteralPath $ArtifactZip -Stream Zone.Identifier -ErrorAction SilentlyContinue
```

artifact ZIP 摘要必须逐字等于上方 `9973...cb11`。随后使用**文件资源管理器的“全部解压缩”**
把 artifact ZIP 解压到 `$TestRoot\artifacts`；再对里面的安装包检查摘要和 MOTW：

```powershell
$CandidateZip = "$TestRoot\artifacts\会议室预约系统-V2.5.0-安装包.zip"
Get-FileHash -Algorithm SHA256 -LiteralPath $CandidateZip
Get-Item -LiteralPath $CandidateZip -Stream Zone.Identifier -ErrorAction SilentlyContinue
```

安装包摘要必须逐字等于上方 `4e8a...151f5`。再次使用**文件资源管理器的“全部解压缩”**
完整解压安装包到 `$TestRoot\candidate`，不要在 ZIP 预览窗口运行，也不要单独复制 BAT。
解压后定位 `安装V2.5.0.bat` 并检查其 MOTW：

```powershell
$InstallerBat = Get-ChildItem -LiteralPath "$TestRoot\candidate" `
  -Filter '安装V2.5.0.bat' -File -Recurse | Select-Object -First 1
$InstallerBat | Select-Object FullName
Get-Item -LiteralPath $InstallerBat.FullName -Stream Zone.Identifier `
  -ErrorAction SilentlyContinue
```

在浏览器下载的 artifact ZIP 上应能看到 `Zone.Identifier`。资源管理器是否把 MOTW 传播到
内层 ZIP/BAT，取决于 Windows 版本和策略，必须原样记录。不要运行 `Unblock-File`。若最外层
浏览器下载 ZIP 都没有 MOTW，仍可继续做安装功能验收，但 SmartScreen 项只能记为
`SKIP（下载链路未保留 MOTW）`，不能记 PASS。

文件缺失、任一摘要不符或 artifact 已过期时立即停止；不要触发新构建、不要改测别的 SHA，
也不要用旧版候选冒充 V2.5.0。

### 2.2 命令行下载仅作备用

浏览器无法下载时，可用 GitHub CLI 取得同一 artifact 做完整性和安装功能验收：

```powershell
gh auth status
gh run download 33244067191 `
```

`SKIP（CLI 下载不构成 MOTW 证据）`。其它步骤仍须按 2.1 的摘要、完整解压和文件定位要求执行。

## 5. A 组：普通用户、SmartScreen 与 UAC

全程从普通非管理员桌面开始，不要先打开管理员终端运行安装 BAT。

### A1：UAC 取消必须无副作用

1. 双击解压目录中的 `安装V2.5.0.bat`。
2. 记录是否出现 SmartScreen、文案、发布者名称和文件来源；不要关闭安全功能。若需要继续，
   由用户本人选择“更多信息 / 仍要运行”，并记录这是未签名内部候选。
3. 按控制台提示准确输入 `YES`。
4. UAC 出现后由用户点击“否”或“取消”。
5. 截图保存为 `A1-smartscreen.png`、`A1-uac-cancel.png`，不包含账号或机器私密信息。
6. 回到管理员 PowerShell，重跑第 4 节。安装根、注册表、两项任务、两条防火墙规则仍应
   不存在，8080 仍无监听。

任一固定对象被创建即判 A1 FAIL，并保留现场，不继续安装。

### A2：UAC 接受并完成全新安装

1. 再次从普通用户双击 `安装V2.5.0.bat`，输入 `YES`。
2. UAC 出现后由用户确认显示的程序/发布者，再点击“是”并提供管理员凭据。
3. 安装必须完成到固定目录 `%ProgramFiles%\会议室预约系统V2`，不能要求自选目录。
4. 控制台必须给出明确成功结果；保存 `A2-install-complete.png`。
5. 在管理员 PowerShell 核对：

```powershell
$InstallRoot = "$env:ProgramFiles\会议室预约系统V2"
Get-Content -LiteralPath "$InstallRoot\版本.txt"
Get-Content -LiteralPath "$InstallRoot\_程序文件\data\install.json" -Raw
Invoke-RestMethod http://127.0.0.1:8080/healthz | ConvertTo-Json -Depth 5
```

预期版本为 `2.5.0`，健康接口为 V2 generation 2、`bind_mode=loopback`、
`setup_complete=false`，且存在稳定 `install_id`。GitHub 证据只记录 install_id 的前 8 位。

## 6. B 组：首次设置、帮助中心与局域网切换

### B1：设置前仅回环

1. 本机打开 `http://127.0.0.1:8080/`，应进入首次设置。
2. 本机打开 `http://127.0.0.1:8080/help`，未登录也应看到离线帮助中心。
3. 抽查帮助中心：9 个分类、55 篇文章可检索；刷新文章 hash URL 不丢内容；浏览器后退正常。
4. 从第二台同局域网设备访问 `http://<Windows-LAN-IP>:8080/`，此时必须失败。

Windows LAN IP 可用以下命令只读查找；报告中只写脱敏网段，例如 `192.168.x.x`：

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.PrefixOrigin -ne 'WellKnown' } |
  Select-Object InterfaceAlias, IPAddress, PrefixLength
```

### B2：合成首次设置

只使用明显的合成值，例如管理员 `test-admin`、笔录室“测试一室/测试二室/测试三室”。
不要使用真实姓名、单位、案号、密码或联系方式。完成设置后核对：

- 服务自动切换到 `bind_mode=lan`，`install_id` 不变；
- 本机登录成功，版本仍为 2.5.0；
- 登录侧栏的“帮助中心”直接打开同一完整阅读器，无中间空页或 503；
- `/help`、`/help/`、`/help/index.html` 与一个未知深路径均显示帮助阅读器，而不是主 SPA；
- 第二台设备此时可以访问 Windows LAN URL。

## 7. C 组：带一定合成数据的真实体验

不要导入数据库。通过正式 UI 手工建立以下最小数据集：

- 3 个测试笔录室；
- 1 名合成管理员、2 名合成员工；
- 至少 8 条预约，跨今天、明天和之后日期，覆盖 3 个房间、4 个标签槽；
- 至少 1 条编辑、1 条取消、1 次普通交接接受、1 次管理员直接指派；
- 至少 1 次同一房间同一时段冲突，必须有且只有一方成功，另一方收到明确冲突提示。

体验并记录：

1. 日历、我的预约、预约记录、工作交接、数据中心、个人中心、系统状态之间切换无报错。
2. 侧栏计数、空状态、加载状态、抽屉焦点返回和 Esc 行为符合界面文案。
3. 取消记录只显示“已取消”；已交接记录保留事件链，不混淆预约者与当事人。
4. 员工只能看到本人历史和统计；管理员可看全单位，前端隐藏不作为唯一权限边界。
5. CSV 仅导出合成数据，下载文件不上传 GitHub。
6. 帮助中心从登录页与侧栏进入均可用，搜索、分类、文章链接与返回路径一致。

## 8. D 组：第二设备与公开大屏

网络配置文件必须是 DomainAuthenticated 或 Private；若实际是 Public，记录环境阻断并停止，
不要临时关闭防火墙或扩大规则来获得通过。

在第二台同局域网设备上：

- 登录管理员与员工各一次，验证角色边界；
- 打开公开大屏，确认不出现事项、备注、案号、完整当事人、部门或内部标签；
- 两台设备同时提交同一空时段，确认只成功一条，另一条明确返回冲突；
- 连续刷新 30 分钟，页面不累积错误提示、不退出到损坏状态。

## 9. E 组：标准用户 DACL

退出所有管理员 PowerShell，回到普通非管理员 PowerShell。程序版本与健康接口应可读；app
写入以及 data/backups/logs 列举必须被拒，命令报 Access denied 是预期 PASS。若受保护路径
写入或列举意外成功，立即截图、停止后续测试，并由管理员在保留证据后只删除该测试文件。

```powershell
$InstallRoot = "$env:ProgramFiles\会议室预约系统V2"
Get-Content -LiteralPath "$InstallRoot\版本.txt"
Set-Content -LiteralPath "$InstallRoot\_程序文件\app\should-not-write.txt" -Value test
Get-ChildItem -LiteralPath "$InstallRoot\_程序文件\data"
Get-ChildItem -LiteralPath "$InstallRoot\_程序文件\backups"
Get-ChildItem -LiteralPath "$InstallRoot\_程序文件\logs"
Invoke-WebRequest http://127.0.0.1:8080/healthz -UseBasicParsing
```

预期：程序版本可读，app 写入被拒，data/backups/logs 不能列举，浏览器与健康接口可用。

## 10. F 组：计划任务、注册表与防火墙

在管理员 PowerShell 中只读核对：

```powershell
$main = Get-ScheduledTask -TaskName '会议室预约系统 V2'
$backup = Get-ScheduledTask -TaskName '会议室预约系统 V2 每日备份'
$main | Select-Object TaskName, State, Principal, Settings, Triggers, Actions
$backup | Select-Object TaskName, State, Principal, Settings, Triggers, Actions
Get-ItemProperty HKLM:\Software\MeetingRoomReservationV2

Get-NetFirewallRule -DisplayName '会议室预约系统V2-手动','会议室预约系统V2-后台' |
  ForEach-Object {
    $_
    $_ | Get-NetFirewallPortFilter
    $_ | Get-NetFirewallAddressFilter
    $_ | Get-NetFirewallApplicationFilter
  }
```

预期：

- 两项任务都由 SYSTEM / Highest 运行；主任务有开机触发器；备份任务为每天本地 02:00、
  StartWhenAvailable、IgnoreNew；
- 两项任务的 `DisallowStartIfOnBatteries` 与 `StopIfGoingOnBatteries` 均为 false；
- 两条规则均为 Inbound / Allow / TCP 8080 / Domain,Private / LocalSubnet，程序分别绑定
  `python.exe` 与 `pythonw.exe`，Public 不开放；
- HKLM 的 InstallRoot、InstallId、任务名、防火墙名与磁盘安装身份一致。

## 11. G 组：端口冲突不杀未知进程

本组只操作测试安装和本机临时 listener：

1. 双击安装根的 `④ 停止本次后台系统.bat`，由用户接受 UAC，确认 8080 释放。
2. 在普通 PowerShell 创建临时 listener，并保持窗口不要关闭：

```powershell
$listener = [Net.Sockets.TcpListener]::new([Net.IPAddress]::Loopback,8080)
$listener.Start()
```

3. 双击 `① 启动系统.bat` 并接受 UAC。产品必须明确报告 8080 被占用，不杀临时 listener，
   也不改用其他端口。
4. 回到 listener 窗口执行 `$listener.Stop()`。
5. 再次双击 `① 启动系统.bat`，服务应恢复，健康接口回到 200。

若产品杀死未知 listener、随机换端口或无提示挂起，判为发布阻断 FAIL。

## 12. H 组：立即备份与恢复闭环

仅在当前数据库全部为合成数据时执行：

1. 创建一条名称明显为“恢复前应保留”的合成预约。
2. 双击 `② 立即备份.bat`，接受 UAC，确认窗口明确报告成功。
3. 再创建一条“恢复后应消失”的合成预约，记录当前页面截图。
4. 双击 `⑥ 从备份恢复.bat`，接受 UAC；确认它只列出当前安装受保护 backups 目录中的
   配对备份，按提示输入 `RESTORE`。
5. 恢复完成后重新登录：第一条预约存在，第二条预约消失，服务健康，旧会话失效或重新
   鉴权，install_id 不变。
6. 在管理员 PowerShell 核对 backups 中每个 `.db` 都有配对 `.json`，且没有
   `-wal`、`-shm`、`-journal` 或隐藏 `.part-*` 残留。

这是有意回退合成数据的破坏性测试。若误用了真实数据，立即停止，不要执行恢复。

## 13. I 组：真实重启、补跑与笔记本电池

1. 重启前记录健康接口、脱敏 install_id、任务状态和最新备份序列。
2. 由用户执行真实 Windows 重启。
3. 在 Windows 用户尚未登录时，从第二台设备访问 LAN URL；开机任务应已使服务可用。
4. 登录后再次核对 `/healthz`、main task Running、备份任务 LastTaskResult/NextRunTime，
   install_id 与合成数据不变。
5. 若是笔记本，在不关闭安全软件的前提下短暂切换电池/外接电源，服务不得因任务计划程序
   电池默认策略自停。
6. 能跨 02:00 挂机时，验证真实每日备份；不能等待则标记 SKIP/待过夜，不得写成 PASS。
7. 将最后一次成功备份时间临时跨过一天的场景留给专门维护窗口；没有执行就标记 SKIP，
   不要修改系统时间冒充证据。

## 14. J 组：Windows 视觉、键盘与长时间体验

至少检查 1024×720、1280×720、1440×900、1920×1080 四档浏览器 viewport；实际显示器

## 15. K 组：SmartScreen、EDR 与签名状态

如实记录：

- 安装 ZIP 与 BAT 的 Mark-of-the-Web、SmartScreen 提示和发布者显示；
- Defender/第三方 EDR 是否告警、隔离、阻断或放行；
- AppLocker、单位组策略是否阻断脚本、冻结 Python 或计划任务；
- 当前候选无 Authenticode 签名，因此签名验签必须记为 FAIL/待签名，而不是 PASS。

不得把“点击仍要运行”写成签名门禁通过。签名后需要对最终签名制品重新计算 SHA-256，
并重做 SmartScreen/EDR/发布者验收。

## 16. 判定规则

以下任一项失败即阻断 Windows 外发：

- 摘要或源码身份不符；UAC 取消产生系统副作用；安装失败或安装到非固定根；
- 设置前可从 LAN 访问，或设置后第二设备无法访问；
- 标准用户能修改程序或读取 data/backups/logs；
- 任务、防火墙、注册表身份不一致，Public 网络被开放；
- 端口冲突会杀未知进程或换端口；备份/恢复丢失应保留数据或留下不一致伴随文件；
- 重启后服务不恢复、合成数据丢失；主要页面在目标分辨率不可操作；
- SmartScreen/EDR/组策略出现无法接受的阻断；Authenticode 仍未完成。

允许标记 SKIP 的只有明确需要等待或外部条件的项目，例如另一台设备、过夜 02:00、两小时
大屏、目标单位 EDR 或证书；每个 SKIP 都必须说明责任人和补测时间，不能把整体写成 PASS。
