停用（编辑用户里关闭「启用账户」开关）的效果：

| 项 | 结果 |
| --- | --- |
| 登录 | 立即无法登录，已登录会话立即失效 |
| 历史预约 | **全部保留**，日历和历史中照常显示 |
| 统计 | 数据中心仍统计其历史工作量 |
| 交接 | 不再出现在交接/指派的可选人列表中 |

## 停用 vs 删除

系统**没有删除用户**的功能，只有停用。人员会流动，但已保存预约仍是历史事实；停用不会把预约改成另一位用户，也不会自动取消未来预约。

## 人员离职的标准操作

1. 停用账户（收回访问权）；
2. 重新读取并检查他名下的**未来有效预约**：按业务决定取消，或由管理员使用「指派给同事」转给启用用户；
3. 检查是否有待处理交接请求。停用接口会使会话失效，但不会替代管理员逐项处理未来安排。

> 当前代码路径不会在停用用户的同一保存动作中自动撤回所有待交接请求；这是运维检查项，不应在文档中包装成自动完成。若旧页面仍显示请求，刷新并以预约详情的当前状态为准。
