# V2.0.0 产品契约

本文档是 V2.0.0 正式实现的产品真值。冻结视觉证据位于原型仓库；本文只固定业务、权限、数据和发布边界。

## 1. 版本定位

- 对外版本号是 `V2.0.0`。
- V2 是全新安装基准，不导入、不读取、不转换 V1 的账号、笔录室、预约或配置。
- 安装器不搜索、不删除、不覆盖 V1 目录。用户若要复用目录名，必须先自行清空并明确选择目标目录。
- 以后只支持 V2 代际内的累计升级；V1 数据库或缺少代际标识的数据库一律拒绝。

## 2. 角色与可见性

角色枚举固定为 `admin | employee`，数据库、API 和前端不得引入 `staff` 等别名。

| 能力 | employee | admin |
| --- | --- | --- |
| 登录后查看全单位预约日历及完整预约详情 | 是 | 是 |
| 创建预约 | 是 | 是 |
| 修改或取消本人预约 | 是 | 是 |
| 修改或取消他人预约 | 否 | 是 |
| 查看预约记录 | 仅本人 | 全单位，可按用户筛选 |
| 管理笔录室、用户、系统 | 否 | 是 |
| 查看公开大屏 | 无需登录 | 无需登录 |

任何前端隐藏都不构成权限边界；Flask 必须对每次读取和写入重新鉴权。系统必须始终保留至少一名启用管理员。

## 3. 预约规则

- 时间以服务器所在本地时区处理，业务日期和时分使用不带时区的规范字符串传输。
- 默认 30 分钟一个占用槽，单次预约最长 180 分钟；实际工作时段由首次设置保存。
- 创建或修改时，预约主记录、全部占用槽和追加式事件必须在同一个 `BEGIN IMMEDIATE` 事务中提交。
- `(room_id, booking_date, slot_start)` 必须有数据库唯一约束，不能只在应用层检查冲突。
- 修改必须带 `expected_revision`。版本不一致返回 `409 REVISION_CONFLICT` 和当前记录，前端保留用户草稿。
- 时段冲突返回 `409 SLOT_CONFLICT` 和最少必要的冲突字段。
- 取消采用状态变更并追加事件，不物理删除预约。

## 4. 标签与偏好

- 标签槽 1、2 是管理员维护的全局标签。
- 标签槽 3、4 是每个用户独立维护的个人标签。
- 每次预约保存 `tag_label_snapshot`，以后改名不改写历史含义。
- 管理员查看历史时，只有先选择预约所有人，才能用该用户的个人标签筛选。
- 个人设置包括默认时长、默认笔录室、预约变更通知和预约提醒；不包含手机、邮箱、头像或额外密码入口。

## 5. 公开大屏

公开接口是无需登录的局域网页面，但响应必须由服务端白名单生成。只允许输出：

- 服务端日期、时间、连接状态和最后更新时间；
- 笔录室的稳定标识和名称；
- 当前及下一时段；
- 当前及下一位访客的服务端脱敏姓名。

不得输出完整姓名、工作人员身份、案号、用途、备注、标签、电话或部门。客户端不得接收完整值后再遮罩。

## 6. 首次设置与运行

- 首次设置前服务只绑定 `127.0.0.1:8080`。
- 首次向导在一个事务中创建首名管理员、至少一个笔录室、工作时间，并写入 `product_generation=2`、`schema_version=1`、`setup_complete=1`。
- 不提供默认账号或默认密码文件。
- 设置完成后由服务管理器重启，才允许绑定 `0.0.0.0:8080`。
- 端口 8080 被占用时必须停止并报告，不能杀死未知进程或随机换端口。

## 7. 明确不在 V2.0.0

- 手机端专项适配；
- 云端托管、跨公网访问或多组织租户；
- 短信、微信、邮件或 Windows 原生通知；
- AI 功能；
- V1.1.0 的任务、签到或工作流模块；
- V1 数据迁移工具。
