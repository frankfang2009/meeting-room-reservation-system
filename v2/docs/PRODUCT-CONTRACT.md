# V2.0.0 产品契约

本文档是 V2.0.0 正式实现的产品真值。冻结视觉证据位于原型仓库；本文只固定业务、权限、数据和发布边界。

## 1. 版本定位

- 对外版本号是 `V2.0.0`。
- V2 是全新安装基准，不导入、不读取、不转换 V1 的账号、笔录室、预约或配置。
- 安装器不搜索、不删除、不覆盖 V1 目录。用户若要复用目录名，必须先自行清空并明确选择目标目录。
- V2.0.0 不提供在线升级入口。仓库中的 `update_core.py` 只是未来 V2 代际内累计
  升级的非生产前置层；任何未来更新都必须拒绝 V1 数据库或缺少代际标识的数据库。
- `/healthz` 的安装标识与具体恢复码只向回环请求返回；局域网请求只能看到通用
  健康状态、产品代际、初始化状态、绑定模式与端口。

## 2. 角色与可见性

角色枚举固定为 `admin | employee`，数据库、API 和前端不得引入 `staff` 等别名。

| 能力 | employee | admin |
| --- | --- | --- |
| 登录后查看全单位 active 预约日历及完整预约详情 | 是 | 是 |
| 创建预约 | 是 | 是 |
| 修改或取消本人预约 | 是 | 是 |
| 修改或取消他人预约 | 否 | 是 |
| 查看预约记录 | 仅本人 | 全单位，可按用户筛选 |
| 管理笔录室、用户、系统 | 否 | 是 |
| 查看公开大屏 | 无需登录 | 无需登录 |

任何前端隐藏都不构成权限边界；Flask 必须对每次读取和写入重新鉴权。系统必须始终保留至少一名启用管理员。
已取消预约不再属于共享日历详情范围；普通员工只能读取本人已取消记录，
管理员仍可读取全单位已取消记录。

## 3. 预约规则

- 预约业务日期和时分以服务器所在本地时区处理，使用不带时区的规范字符串传输；
  `created_at`、`updated_at`、事件与审计等技术时间戳统一使用 UTC RFC3339（`Z`）。
- 默认 30 分钟一个占用槽，单次预约最长 180 分钟；实际工作时段由首次设置保存。
- 创建或修改时，预约主记录、全部占用槽和追加式事件必须在同一个 `BEGIN IMMEDIATE` 事务中提交。
- `(room_id, booking_date, slot_start)` 必须有数据库唯一约束，不能只在应用层检查冲突。
- 修改必须带 `expected_revision`。版本不一致返回 `409 REVISION_CONFLICT` 和当前记录，前端保留用户草稿；
  重新检查按稳定预约 ID 读取最新记录并更新比较基线，不得覆盖本地草稿。
- 时段冲突返回 `409 SLOT_CONFLICT` 和最少必要的冲突字段；即使冲突直到槽位
  唯一约束写入阶段才暴露，错误码与最小冲突投影也必须保持一致。冲突重检应重新读取
  目标日期并明确返回“仍被占用”或“已可用”的用户反馈。
- `purpose`（预约用途）是创建和修改都必须提供的非空字段；前后端不得在缺失时
  自动填入“工伤笔录”或任何演示默认值。
- 取消采用状态变更并追加事件，不物理删除预约。
- 预约记录的“加载更早月份”在当前列表底部追加，并用月份分隔线区分；同月游标分页与
  跨月追加必须复用当前范围、用户、笔录室、状态、标签和搜索筛选。月份步进或下拉选择
  新月份时重置为该月的单月列表。
- 短暂操作提示必须携带 `success | info | error` 语义；失败、权限不足、时段已开始和网络
  错误不得显示成功对勾。提示继续使用礼貌级实时播报，并允许用户主动关闭。
- 预约、日历、历史、用户和审计区的非模态弹层必须支持 Esc 与外部点击关闭；Esc 或
  弹层内的完成动作关闭后把焦点还给触发按钮，外部点击则保留用户刚选择的新焦点目标。
- 预约开始前，本人或管理员可以修改、取消；预约开始后到结束前只能由本人或
  管理员取消，不能再修改开始时间或既有事实；预约结束后完全只读。
- 预约者姓名使用创建时保存的 `owner_name_snapshot` 展示。以后修改个人姓名只
  影响新预约，不追改既有预约与历史归属。

## 4. 标签与偏好

- 标签槽 1、2 是管理员维护的全局标签。
- 标签槽 3、4 是每个用户独立维护的个人标签。
- 每次预约保存 `tag_label_snapshot`，以后改名不改写历史含义。
- 个人默认标签保存 `1..4 | null` 槽位引用，不存标签文案；全局或个人标签改名后
  仍指向同一语义槽位。它只预选之后打开的空白新建单，不覆盖编辑单、会话恢复草稿、
  冲突保留草稿或跨页待续草稿。
- 管理员查看历史时，只有先选择预约所有人，才能用该用户的个人标签筛选。
- 历史中的笔录室和标签过滤都只能选择一个值，必须使用 radio 语义并提供明确的
  “全部”选项；月份步进与月份菜单同样只允许最近 12 个月。
- 个人中心包括两个相互独立的页签：只读的“我的活动”和可编辑的“偏好设置”。
- “我的活动”只聚合当前登录用户本人预约，不提供全单位排行、他人数据或跨用户比较。
  已完成预约定义为 `status=active` 且结束时间不晚于服务端当前本地时间；已取消、
  尚未开始和进行中的预约不计入完成数、时长、活跃天数与概览。
- “我的活动”仅展示活动概览和四项汇总，不展示热力图、日期范围、月份标签、按日
  下钻、最近完成或排行，避免在低频个人页面制造无必要的信息密度。
- 偏好设置包括默认时长、默认笔录室、默认标签、个人标签 3/4、预约变更通知和预约提醒；
  预约提醒可选择开始前 15、30 或 60 分钟，关闭时保留选择。临近提醒的查询与确认
  始终按当前偏好计算同一窗口，不为单次预约保存提前量快照；缩短窗口后已移出的提醒
  不再允许确认；
  默认首页是按登录用户隔离的当前浏览器偏好，不宣称跨设备同步。
  偏好页不包含手机、邮箱、头像上传、额外密码入口或外部社交资料。
- 保存个人设置时姓名不能为空；请求进行中保存与退出操作必须禁用并显示 busy 状态，
  避免重复提交或在响应前离开会话。
- 未开始的 active 预约允许预约本人或管理员从详情抽屉复制对外提醒信息。个人模板只允许
  使用当事人姓名、日期、开始时间、结束时间和笔录室 5 个前端变量，案号、用途、备注
  永远不进入变量集合。系统只把前端拼装结果复制到剪贴板，由用户自行发送；不自动发送、
  不跳转外部应用、不记录已发送状态，也不提供每房间、每预约或多模板管理。因此它不属于
  §8 排除的系统自动通知通道。

## 5. 公开大屏

公开接口是无需登录的局域网页面，但响应必须由服务端白名单生成。只允许输出：

- 服务端日期、时间、连接状态和最后更新时间；
- 笔录室的稳定标识和名称；
- 当前及下一时段；
- 当前及下一位访客的服务端脱敏姓名。

不得输出完整姓名、工作人员身份、案号、用途、备注、标签、电话或部门。客户端不得接收完整值后再遮罩。

## 6. 首次设置与运行

- 正式安装路径固定为 `%ProgramFiles%\会议室预约系统V2`。程序文件只允许普通
  用户读取和执行，`data`、`backups`、`logs` 只允许 `SYSTEM` 与 Administrators
  访问；安装、启动和更新都必须复核 Windows DACL。
- 首次设置前服务只绑定 `127.0.0.1:8080`。
- 首次设置提交同时要求客户端地址为 loopback，且 `Host` 只能是固定 8080 端口上的
  `localhost` 或回环 IP 字面量；不得解析或接受任意域名。
- 首次向导在一个事务中创建首名管理员、至少一个笔录室、工作时间，并写入 `product_generation=2`、`schema_version=2`、`setup_complete=1`。
- 产品代际 2 的 schema v1 数据库必须在服务对用户可用前，以一个 `BEGIN IMMEDIATE`
  事务幂等迁移至 schema v2。迁移只补充缺失列并更新结构版本，不改写业务数据；
  任一失败必须整体回滚并进入恢复状态。这不改变“V2 不读取、不迁移产品 V1 数据”的代际边界。
- 首次设置后，管理员可在系统状态页以安静的抽屉编辑入口修改工作时间。
  新时间只影响未来可用时段、日历动态上限、today 时间线与集成 availability；
  已有预约的日期和时间不追溯改写，即使落在新工作时间外也必须在日历与历史中保持可见。
- 不提供默认账号或默认密码文件。
- 设置完成后由服务管理器重启，才允许绑定 `0.0.0.0:8080`。
- 端口 8080 被占用时必须停止并报告，不能杀死未知进程或随机换端口。
- `install.json.setup_complete=true` 时，数据库缺失、为空、损坏或回退到未设置
  状态都必须拒绝重新初始化，不得把镜像从 true 降为 false，也不得重新开放首次
  设置；只能引导管理员从受验证备份恢复。
- 系统按服务器本地日历日每天 02:00 自动备份，并在超过 24 小时没有成功备份时
  于服务启动后补做；仅保留最近 30 份校验通过的备份。备份主数据库必须在落盘前
  退出 WAL 模式，成功、失败与轮转路径都不得遗留对应的 `-wal`、`-shm`、
  `-journal` 或隐藏 `.part-*` 伴随文件。恢复只能通过本机 UAC 提权工具执行。
  仅在锁记录安装身份与进程身份可验证且原进程已结束或 PID 已复用时，才可回收
  崩溃遗留的维护锁。schema v1 备份经侧车、哈希、代际和业务完整性预检后可恢复；
  原子替换后必须复用同一 schema v1→v2 迁移，失败则回滚到恢复前现场。
- 备份管道失败必须稳定返回 `BACKUP_FAILED`。失败审计的二次写入异常只记入
  服务日志，不得覆盖对管理员的备份错误码。
- 登录会话空闲 30 分钟或累计 12 小时后失效。提醒、系统状态与管理员笔录室统计等
  后台 GET 轮询不延长空闲会话；用户主动读取日历等业务操作仍更新活动时间。
- 会话过期时，未保存的预约表单与待续草稿只写入当前标签页的 `sessionStorage`，
  并按原登录用户 ID 隔离。重新认证完成 session 与 bootstrap 双重校验后才恢复；
  换用其他账号不可见，主动退出会清除当前账号草稿。过期层必须明确说明
  “本标签页内的预约草稿已保留，使用同一账号重新登录后可以恢复”，不得笼统承诺保存其他页面状态。
- 日历的方向键导航按时段行与笔录室列计算；跳过禁用或占位格时不得串列或跨行。
- 日历日期跳转和前后日按钮只开放服务器业务日的前后两年；创建、修改预约的开始时间
  必须在请求发出前按服务端 `slotMinutes` 对齐。员工没有可用笔录室时应留在当前页并
  明确提示联系管理员，不得静默落到无可操作内容的日历。
- 所有可操作控件的命中区域不得小于 44×44px；紧凑图标可以保持原视觉尺寸，但抽屉
  返回、提醒确认、地址复制和删除笔录室等低频操作也不能缩小可点击区域。
- 日历预约数据必须与请求日期绑定。切换日期时，旧日期预约不得出现在新日期标题下；
  新数据返回前保留日期控件、笔录室标题、时间轴与安静的骨架条。
- 1024×720 档位下，三间笔录室必须完整适配日历可用宽度，不得产生文档级或 8px 的
  日历内部横向滚动；更多笔录室可在日历容器内部滚动，但不得撑宽整个页面。
- 960px、720px 与 620px 宽度规则只是桌面窗口意外缩小时的防崩坏保护，不属于正式验收档位，
  也不代表 V2.0.0 支持手机或平板产品体验。
- 预约时长固定使用 30–180 分钟视觉比例尺，只显示 60/90/120/150 四个内部停止点；
  停止点必须随当前选择与动态可用上限呈现已选、可用、不可用状态。
- 抽屉打开时，底部 toast 和变更提醒必须随主工作区进入 `inert`；预约变更记录读取失败
  必须提供原地重试。历史“已取消”文字与其底色对比度不得低于 4.5:1。

## 7. 局域网安全边界

- V2.0.0 仅支持可信的 Windows Domain/Private 局域网，防火墙范围固定为
  `LocalSubnet`；禁止公网映射、访客 Wi-Fi、不受控 VPN 或跨公网部署。
- V2.0.0 仍使用 HTTP。账号口令和预约信息会在可信局域网内明文传输，部署方必须
  通过 VLAN、终端访问控制和物理管理承担该风险；后续版本再提供受管 TLS。
- 公开大屏只接受服务端白名单投影；认证接口使用 HttpOnly、SameSite=Strict
  Cookie、CSRF、双层登录限速和有界会话。
- 未取得 Authenticode 代码签名证书前，安装包只能通过受控内部渠道分发并带外核对
  SHA-256；不得将未签名候选标为允许正式外发。

## 8. 明确不在 V2.0.0

- 手机端专项适配；
- 云端托管、跨公网访问或多组织租户；
- 系统自动发送的短信、微信、邮件或 Windows 原生通知；
- AI 功能；
- V1.1.0 的任务、签到或工作流模块；
- V1 数据迁移工具。
- V2.0.0 在线或自动升级器（`update_core.py` 不进入生产 payload）。
