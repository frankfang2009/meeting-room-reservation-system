# V2.3.0 产品契约

本文档是 V2.3.0 正式实现的产品真值。冻结视觉证据位于原型仓库；本文只固定业务、权限、数据和发布边界。

## 1. 版本定位

- 对外版本号是 `V2.3.0`；这是 V2.3.x 功能线的首个版本：提醒系统重做（临近提醒
  画进日历、变更通知改为必须确认的居中弹窗、新增提示音偏好），数据库 schema 升至
  v3（提醒回执表按事件维度重建），API 契约同步变更；其余业务规则与 V2.2.x 一致。
- 源代码可按 Apache-2.0 公开协作；源码公开不等于 Windows 安装包正式发布，也不改变
  候选清单中的 `formal_external_release_allowed=false`。
- 仓库、Issue、PR 和 CI 不得接收客户数据库、备份、日志、密钥、真实个人信息或未经
  授权的品牌素材；公开协作只使用合成或不可逆脱敏证据。
- V2 是全新安装基准，不导入、不读取、不转换 V1 的账号、笔录室、预约或配置。
- 安装器不搜索、不删除、不覆盖 V1 目录。用户若要复用目录名，必须先自行清空并明确选择目标目录。
- V2.2.0 提供只面向明确登记 V2 安装根的离线累计升级包，首个支持来源仅为冻结的
  `V2.1.0`。升级包不得联网，不扫描磁盘寻找旧版本，不接触 V1；提交前必须备份并
  验证全部数据，失败时回滚程序与运行状态，保留 `data/`、`backups/`、`logs/`、
  安装身份与 secret。真实 Windows 升级验收和签名完成前，升级包仍不得正式外发。
- `/healthz` 的安装标识与具体恢复码只向回环请求返回；局域网请求只能看到通用
  健康状态、产品代际、初始化状态、绑定模式与端口。
- macOS 自托管版（§10）以 GitHub Release 为正式分发渠道；Windows 安装包与
  升级包在真实 Windows 实机验收和 Authenticode 签名完成前仍不得正式外发。

## 2. 角色与可见性

角色枚举固定为 `admin | employee`，数据库、API 和前端不得引入 `staff` 等别名。

| 能力 | employee | admin |
| --- | --- | --- |
| 登录后查看全单位 active 预约日历及完整预约详情 | 是 | 是 |
| 创建预约 | 是 | 是 |
| 修改或取消本人预约 | 是 | 是 |
| 修改或取消他人预约 | 否 | 是 |
| 查看预约记录 | 仅本人 | 全单位，可按用户筛选 |
| 查看数据中心 | 仅本人服务数据 | 全单位总览、任一人员或本人 |
| 导出 CSV 办件明细 | 仅本人服务数据 | 当前数据中心范围 |
| 管理笔录室、用户、系统 | 否 | 是 |
| 查看公开大屏 | 无需登录 | 无需登录 |

任何前端隐藏都不构成权限边界；Flask 必须对每次读取和写入重新鉴权。系统必须始终保留至少一名启用管理员。
已取消预约不再属于共享日历详情范围；普通员工只能读取本人已取消记录，
管理员仍可读取全单位已取消记录。

## 3. 预约规则

- 预约业务日期和时分以服务器所在本地时区处理，使用不带时区的规范字符串传输；
  `created_at`、`updated_at`、事件与审计等技术时间戳统一使用 UTC RFC3339（`Z`）。
- 默认 30 分钟一个占用槽，单次预约最长 180 分钟；实际工作时段由首次设置保存。
- 创建或修改时，预约主记录、全部占用槽和追加式事件必须在同一个 `BEGIN IMMEDIATE` 事务中提交。
- `(room_id, booking_date, slot_start)` 必须有数据库唯一约束，不能只在应用层检查冲突。
- 修改必须带 `expected_revision`。版本不一致返回 `409 REVISION_CONFLICT` 和当前记录，前端保留用户草稿；
  重新检查按稳定预约 ID 读取最新记录并更新比较基线，不得覆盖本地草稿。
- 时段冲突返回 `409 SLOT_CONFLICT` 和最少必要的冲突字段；即使冲突直到槽位
  唯一约束写入阶段才暴露，错误码与最小冲突投影也必须保持一致。冲突重检应重新读取
  目标日期并明确返回“仍被占用”或“已可用”的用户反馈。
- `purpose`（预约用途）是创建和修改都必须提供的非空字段；前后端不得在缺失时
  自动填入“工伤笔录”或任何演示默认值。
- 取消采用状态变更并追加事件，不物理删除预约。
- 预约记录的“加载更早月份”在当前列表底部追加，并用月份分隔线区分；同月游标分页与
  跨月追加必须复用当前范围、用户、笔录室、状态、标签和搜索筛选。月份步进或下拉选择
  新月份时重置为该月的单月列表。
- 短暂操作提示必须携带 `success | info | error` 语义；失败、权限不足、时段已开始和网络
  错误不得显示成功对勾。提示继续使用礼貌级实时播报，并允许用户主动关闭。
- 预约、日历、历史、用户和审计区的非模态弹层必须支持 Esc 与外部点击关闭；Esc 或
  弹层内的完成动作关闭后把焦点还给触发按钮，外部点击则保留用户刚选择的新焦点目标。
- 预约开始前，本人或管理员可以修改、取消；预约开始后到结束前只能由本人或
  管理员取消，不能再修改开始时间或既有事实；预约结束后完全只读。
- 预约者姓名使用创建时保存的 `owner_name_snapshot` 展示。以后修改个人姓名只
  影响新预约，不追改既有预约与历史归属。

## 4. 标签与偏好

- 标签槽 1、2 是管理员维护的全局标签。
- 标签槽 3、4 是每个用户独立维护的个人标签。
- 每次预约保存 `tag_label_snapshot`，以后改名不改写历史含义。
- 新建和编辑预约继续在一行展示四个标签槽位；较长的自定义名称必须收在各自按钮内以
  省略号呈现，悬停和无障碍名称仍提供完整文案，不得溢出到相邻标签或备注区域。
- 个人默认标签保存 `1..4 | null` 槽位引用，不存标签文案；全局或个人标签改名后
  仍指向同一语义槽位。它只预选之后打开的空白新建单，不覆盖编辑单、会话恢复草稿、
  冲突保留草稿或跨页待续草稿。
- 管理员查看历史时，只有先选择预约所有人，才能用该用户的个人标签筛选。
- 历史中的笔录室和标签过滤都只能选择一个值，必须使用 radio 语义并提供明确的
  “全部”选项；月份步进与月份菜单同样只允许最近 12 个月。
- 个人中心只负责个人资料与工作偏好，不再重复展示活动统计或提供第二套数据中心入口。
  员工和管理员查看本人服务数据时都进入主导航中的“数据中心”。
- 个人中心包括默认时长、默认笔录室、默认标签、个人标签 3/4、预约变更通知、预约提醒
  和提醒提示音；预约提醒可选择开始前 15、30 或 60 分钟，关闭时保留选择。临近提醒的
  查询始终按当前偏好实时计算同一窗口，不为单次预约保存提前量快照；临近提醒是状态而
  不是待办——不提供确认动作，条目随时间自然进入与移出窗口。
- 临近提醒只在页面打开时有效，其常驻形态是画进日历本体：提前窗口内本人预约块上的
  倒计时角标（含紧急态）、侧栏“我的预约”计数徽章；首次进入窗口时做一次性轻提示
  （底部 toast 与温和的提示音，提示音可在个人中心关闭）；翻看其他日期时“今天”按钮
  出现小圆点。系统不发送短信、微信、邮件或系统原生通知（§9 边界不变）。
- 预约变更通知以居中弹窗展示且必须主动确认（Esc 等同确认）：内容包含操作人、时间与
  事件快照的字段级对比（案号、用途、备注只在对比中按需出现）；多条变更聚合成一个
  列表，不逐条打扰。抽屉/表单打开期间通知排队等待，关闭后立即出现；排队期间只显示
  安静的信息条，不与表单抢焦点。确认按变更事件维度记录（schema v3 的
  `notice_receipts`），已确认的变更不再重复出现；超过 45 天未确认的变更事件过期
  不再提示，确认回执保留 90 天后随确认动作清理。
  默认首页是按登录用户隔离的当前浏览器偏好，不宣称跨设备同步。
  偏好页不包含手机、邮箱、头像上传、额外密码入口或外部社交资料。
- 保存个人设置时姓名不能为空；请求进行中保存与退出操作必须禁用并显示 busy 状态，
  避免重复提交或在响应前离开会话。
- 未开始的 active 预约允许预约本人或管理员从详情抽屉复制对外提醒信息。个人模板只允许
  使用当事人姓名、日期、开始时间、结束时间和笔录室 5 个前端变量，案号、用途、备注
  永远不进入变量集合。系统只把前端拼装结果复制到剪贴板，由用户自行发送；不自动发送、
  不跳转外部应用、不记录已发送状态，也不提供每房间、每预约或多模板管理。因此它不属于
  §9 排除的系统自动通知通道。

## 5. 数据中心与办件明细

- 数据中心向 `employee` 与 `admin` 开放。员工的范围由服务端强制固定为本人；管理员
  可查看全单位、本人或指定人员。员工伪造 `overall`、`person` 或其他 `ownerId`
  必须返回 `403`，不得依赖前端筛选实现隔离。
- 默认时间范围为服务端当前自然月，含首尾日期，最长 366 天。可按日期、笔录室、
  标签和关键词筛选；管理员查看全单位时不得使用任何人的个人标签。
- 第一版核心指标固定为：有效预约数量、已结束预约数量、有效预约时长；取消率作为质量
  护栏。已结束预约指 `status=active` 且结束时间不晚于服务端当前时间，不等同于系统
  中存在独立的“已完成”状态；有效预约时长累计全部 `status=active` 预约的起止时长，
  不冒充实际办理耗时。
- 员工页面帮助本人安排工作和复盘：核心指标、预约趋势、个人标签构成、星期×时段
  分布。管理员全单位页面帮助看工作量与资源分布：同一组核心指标、预约趋势、
  笔录室构成、星期×时段分布；选择具体人员后切换到个人视角。全单位页面刻意不提供
  人员构成清单（不渲染全员工作量列表）；如需单人视角，管理员通过人员下拉进入该
  人员的个人视角查看。
- 预约趋势在含首尾不超过 90 天时按自然周展示，超过 90 天时自动切换为
  自然月。悬停或键盘聚焦柱形时显示该周/月在当前筛选内的准确日期区间、有效
  预约场次和总时长；切换到时长指标后，柱顶只显示数字，单位仅在概要中出现。
- 第一版不展示排名、绩效分数、房间利用率、案件数量、平均办理时长或跨员工对比，
  避免把预约记录误解释为绩效或案件口径。每个看板必须显示数据时间范围与生成时间。
- CSV 是当前筛选范围内的办件明细，不是数据库浏览器。状态筛选只接受
  `active | cancelled`；字段、顺序、UTF-8 BOM、CRLF、20,000 行上限和公式注入防护
  由 API 契约固定。导出必须记录不含业务内容的安全审计。

## 6. 公开大屏

公开接口是无需登录的局域网页面，但响应必须由服务端白名单生成。只允许输出：

- 服务端日期、时间、连接状态和最后更新时间；
- 笔录室的稳定标识和名称；
- 当前及下一时段；
- 当前及下一位访客的服务端脱敏姓名。

不得输出完整姓名、工作人员身份、案号、用途、备注、标签、电话或部门。客户端不得接收完整值后再遮罩。
管理员可把个别笔录室移出公开大屏投影；隐藏房间的名称及其预约不得进入公开响应。
这一开关不停用预约日历中的房间，也不改变员工共享日历或只读集成 API。全部房间均
隐藏时公开响应返回空 `rooms`，投影仍由服务端白名单生成。

## 7. 首次设置与运行

- 正式安装路径固定为 `%ProgramFiles%\会议室预约系统V2`。程序文件只允许普通
  用户读取和执行，`data`、`backups`、`logs` 只允许 `SYSTEM` 与 Administrators
  访问；安装、启动和更新都必须复核 Windows DACL。
- 首次设置前服务只绑定 `127.0.0.1:8080`。
- 首次设置提交同时要求客户端地址为 loopback，且 `Host` 只能是固定 8080 端口上的
  `localhost` 或回环 IP 字面量；不得解析或接受任意域名。
- 首次向导在一个事务中创建首名管理员、至少一个笔录室、工作时间，并写入 `product_generation=2`、`schema_version=3`、`setup_complete=1`。
- 产品代际 2 的旧结构数据库必须在服务对用户可用前，以 `BEGIN IMMEDIATE` 事务幂等
  迁移至当前结构版本：v1→v2 只补充缺失列；v2→v3 把提醒回执表重建为事件维度的
  `notice_receipts`（已确认的变更回执按版本关联转换，业务数据不变）并补充提示音
  偏好列。任一步失败必须整体回滚并进入恢复状态。这不改变“V2 不读取、不迁移产品
  V1 数据”的代际边界。
- 首次设置后，管理员可点击系统状态页整行“工作时间”入口打开右侧抽屉修改，
  交互与下方“最近备份”行保持一致，不再额外放置突兀的行内按钮。
  新时间只影响未来可用时段、日历动态上限、today 时间线与集成 availability；
  已有预约的日期和时间不追溯改写，即使落在新工作时间外也必须在日历与历史中保持可见。
- 不提供默认账号或默认密码文件。
- 设置完成后由服务管理器重启，才允许绑定 `0.0.0.0:8080`。
- 端口 8080 被占用时必须停止并报告，不能杀死未知进程或随机换端口。
- `install.json.setup_complete=true` 时，数据库缺失、为空、损坏或回退到未设置
  状态都必须拒绝重新初始化，不得把镜像从 true 降为 false，也不得重新开放首次
  设置；只能引导管理员从受验证备份恢复。
- 系统按服务器本地日历日每天 02:00 自动备份，并在超过 24 小时没有成功备份时
  于服务启动后补做；仅保留最近 30 份校验通过的备份。备份主数据库必须在落盘前
  退出 WAL 模式，成功、失败与轮转路径都不得遗留对应的 `-wal`、`-shm`、
  `-journal` 或隐藏 `.part-*` 伴随文件。恢复只能通过本机 UAC 提权工具执行。
  仅在锁记录安装身份与进程身份可验证且原进程已结束或 PID 已复用时，才可回收
  崩溃遗留的维护锁。schema v1 备份经侧车、哈希、代际和业务完整性预检后可恢复；
  原子替换后必须复用同一 schema v1→v2 迁移，失败则回滚到恢复前现场。
- 备份管道失败必须稳定返回 `BACKUP_FAILED`。失败审计的二次写入异常只记入
  服务日志，不得覆盖对管理员的备份错误码。
- 登录会话空闲 30 分钟或累计 12 小时后失效。提醒、系统状态与管理员笔录室统计等
  后台 GET 轮询不延长空闲会话；用户主动读取日历等业务操作仍更新活动时间。
- 会话过期时，未保存的预约表单与待续草稿只写入当前标签页的 `sessionStorage`，
  并按原登录用户 ID 隔离。重新认证完成 session 与 bootstrap 双重校验后才恢复；
  换用其他账号不可见，主动退出会清除当前账号草稿。过期层必须明确说明
  “本标签页内的预约草稿已保留，使用同一账号重新登录后可以恢复”，不得笼统承诺保存其他页面状态。
- 日历的方向键导航按时段行与笔录室列计算；跳过禁用或占位格时不得串列或跨行。
- 日历日期跳转和前后日按钮只开放服务器业务日的前后两年；创建、修改预约的开始时间
  必须在请求发出前按服务端 `slotMinutes` 对齐。员工没有可用笔录室时应留在当前页并
  明确提示联系管理员，不得静默落到无可操作内容的日历。
- 所有可操作控件的命中区域不得小于 44×44px；紧凑图标可以保持原视觉尺寸，但抽屉
  返回、提醒确认、地址复制和删除笔录室等低频操作也不能缩小可点击区域。
- 日历预约数据必须与请求日期绑定。切换日期时，旧日期预约不得出现在新日期标题下；
  新数据返回前保留日期控件、笔录室标题、时间轴与安静的骨架条。
- 1024×720 档位下，三间笔录室必须完整适配日历可用宽度，不得产生文档级或 8px 的
  日历内部横向滚动；更多笔录室可在日历容器内部滚动，但不得撑宽整个页面。
- 960px、720px 与 620px 宽度规则只是桌面窗口意外缩小时的防崩坏保护，不属于正式验收档位，
  也不代表 V2.2.0 支持手机或平板产品体验。
- 预约时长固定使用 30–180 分钟视觉比例尺，只显示 60/90/120/150 四个内部停止点；
  停止点必须随当前选择与动态可用上限呈现已选、可用、不可用状态。
- 抽屉打开时，底部 toast 和变更提醒必须随主工作区进入 `inert`；预约变更记录读取失败
  必须提供原地重试。历史“已取消”文字与其底色对比度不得低于 4.5:1。

## 8. 局域网安全边界

- V2.2.0 仅支持可信的 Windows Domain/Private 局域网，防火墙范围固定为
  `LocalSubnet`；禁止公网映射、访客 Wi-Fi、不受控 VPN 或跨公网部署。
- V2.2.0 仍使用 HTTP。账号口令和预约信息会在可信局域网内明文传输，部署方必须
  通过 VLAN、终端访问控制和物理管理承担该风险；后续版本再提供受管 TLS。
- 公开大屏只接受服务端白名单投影；认证接口使用 HttpOnly、SameSite=Strict
  Cookie、CSRF、双层登录限速和有界会话。
- 未取得 Authenticode 代码签名证书前，安装包只能通过受控内部渠道分发并带外核对
  SHA-256；不得将未签名候选标为允许正式外发。

## 9. 明确不在 V2.3.0

- 手机端专项适配；
- 云端托管、跨公网访问或多组织租户；
- 系统自动发送的短信、微信、邮件或 Windows 原生通知；
- AI 功能；
- V1.1.0 的任务、签到或工作流模块；
- V1 数据迁移工具。
- 在线或自动升级、远程升级服务与静默后台更新（macOS 版的只读版本检查是
  §10 定义的唯一例外，且严格止步于提示与链接）；
- 原始数据库浏览、任意 SQL 查询或不受字段白名单约束的导出。

## 10. macOS 自托管版

- V2.2.1 新增 macOS arm64（Apple Silicon）自托管版：同一份应用核心打包
  python-build-standalone 冻结运行时与预构建前端，便携目录布局
  `app/ + runtime/ + data|backups|logs`，无安装器、无系统残留，删除应用文件夹
  即彻底卸载；不做 launchd 开机自启，服务以前台方式随 `启动.command` 运行。
- 交付物为可复现 zip（两次独立构建字节一致，进入 CI 门禁）与 DMG（由校验过
  的 zip 内容生成并反向核对关键文件哈希）；运行时 tarball 与全部 wheel 均按
  SHA-256 锁定，SBOM、第三方声明与来源证明随包分发。
- 系统下限 macOS 13；仅 arm64。首次双击从 DMG 挂载卷启动必须被拒绝并提示
  先拖出到可写位置。首次启动自动生成安装身份（`install.json` 与 `install_id`），
  `app/EDITION` 标记 `macos-selfhost` 版本形态。
- 升级方式为手动替换：下载新包 → 停止服务 → 替换 `app/`、`runtime/`、
  保留 `data/`、`backups/`、`logs/`。不提供跨平台（Windows ↔ macOS）数据
  迁移承诺。
- 版本检查是 macOS 版专属能力：至多每 24 小时读取一次 GitHub Release 的固定
  清单（仅 HTTPS、固定主机、10 秒超时、64 KiB 上限、严格 schema 校验），
  请求不携带任何本机数据；结果只在管理员系统状态页显示"有新版本"与发布页
  链接，链接由服务端按内置仓库常量构造，不信任清单自带 URL。任何失败安静
  降级，绝不自动下载、自动安装或影响业务。Windows 版与开发态默认关闭。
- 未签名 DMG 的 Gatekeeper 首启处置如实文档化（右键打开或去除隔离属性），
  不教唆关闭系统安全功能；Developer ID 签名与公证是后续独立决策。
