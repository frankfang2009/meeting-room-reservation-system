## 发现的问题

1. **P1 · 测试机 UAC 管理员提升策略被改为不提示（阻断 A1，污染 A2 子项）**
   - 最短复现：`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System` 中 `ConsentPromptBehaviorAdmin=0`（0=无提示提升），`EnableLUA=1`。安装触发提升时无任何 UAC 界面，直接以管理员运行。
   - 预期：默认值 5（对非 Windows 二进制的提升弹出凭据/同意提示），提示由用户本人操作。
   - 实际：全程零提示。2026-08-28 V2.4.1 轮记录"用户本人 UAC 批准 3 次"，说明该值在 8 月 28 日后被改动（原因不明，非本轮操作）。
   - 是否稳定：稳定复现。是否阻断：**阻断 A1 的取消路径与 A2 的用户确认子项**；不阻断其余各组。
   - 证据：`evidence/machine-and-admin.txt`（EnableLUA/组读取）；本文件 A1/A2 行。
   - 责任人：用户恢复默认值（ConsentPromptBehaviorAdmin=5）后补测 A1/A2 的 UAC 交互，并核查该改动来源。

2. **P2 · 管理员"直接指派"经详情抽屉发起时表现为"交接处理中"（待接受），非立即生效**
   - 最短复现：管理员打开预约详情 → 交接给同事 → 选择员工 → 发起；发起方详情按钮变为"交接处理中"（disabled），预约者仍为管理员。
   - 预期（按 PRODUCT-CONTRACT/AGENTS 语义）：管理员直接指派应立即生效并为接手方生成不可拒绝的指派结果通知。
   - 实际：本轮该入口产生的是与普通交接一致的待接受请求（"交接处理中"）。**可能存在独立的"管理员直接指派"入口未在 UI 中定位**，或该入口语义与文档不符。
   - 是否稳定：稳定。是否阻断：不阻断本轮（普通交接闭环已验证）；需产品侧澄清。
   - 证据：`screenshots` 会话记录；004 详情"交接处理中"（disabled）。
   - 责任人：产品/开发澄清指派入口与语义；执行者按澄清结果补测。

3. **P3 · Windows 双绑定语义下"端口占用"场景表现为启动失败而非"端口占用"文案**
   - 最短复现：临时程序绑定 127.0.0.1:8080（lan 模式服务绑定 0.0.0.0:8080）→ ① 启动系统。
   - 预期（指南 §11）：产品明确报告 8080 被占用。
   - 实际：Windows 允许两绑定共存；服务绑定成功但健康检查（走 127.0.0.1）被 listener 截胡 → ① 以 rc=1 fail-closed 报"启动没有完成"。核心安全契约（不杀未知进程、不换端口、不静默降级）全部保持。
   - 是否稳定：稳定。是否阻断：不阻断（fail-closed 语义保持）；建议产品在绑定阶段显式探测 127.0.0.1:8080 冲突并给出占用文案。
   - 证据：`evidence/g-start-output.txt`、`evidence/g2-run.txt`。
   - 责任人：开发评估；不构成 Windows 外发阻断。
