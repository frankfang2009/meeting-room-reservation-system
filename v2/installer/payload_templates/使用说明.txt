会议室预约系统 V2.5.1 使用说明
===============================

安装与安全边界
  - 正式安装根固定为“%ProgramFiles%\会议室预约系统V2”，不支持移动到其他目录运行。
  - ①–⑥六个工具都会请求 UAC 管理员授权。执行前会交叉核对固定安装根、
    install.json、install_id、HKLM 中的 TransactionInstallId/InstallId/SecurityInstallId，
    以及主任务、每日备份任务和两条防火墙规则的安装身份；计划任务还会
    核对 SYSTEM 运行主体、程序路径、参数、工作目录和 02:00 补跑设置。不一致时直接拒绝。
  - “_程序文件\app”和运行时对普通 Users 仅开放读取/执行；“data”、
    “backups”、“logs”及其内容仅 SYSTEM 和 Administrators 可访问。

① 启动系统
  由当前安装专属的 SYSTEM 计划任务启动 V2。启动后通过 service.py --check
  验证服务身份和健康状态，再打开本机浏览器。手动启动不会改变原有开机启动设置。

② 立即备份
  调用“_程序文件\app\backup.py --scheduled --expected-install-id <当前 install_id>”
  执行 SQLite 一致性备份。数据库备份和它的 JSON 校验 sidecar 成对写入受保护的
  “_程序文件\backups”。普通用户无法直接读取，如需导出请联系维护人员。
  安装器还建立每日 02:00 的 SYSTEM 备份任务；错过计划时间后由 StartWhenAvailable
  在下次可运行时补跑，并使用 IgnoreNew 防止重复并发。

③ 设置开机自动启动
  启用主任务、每日备份任务和当前安装的两条局域网防火墙规则，启动并复检服务。

④ 停止本次后台系统
  临时保护主任务不会在停止期间重启服务，仅调用“_程序文件\app\service.py --stop”
  按 PID 身份令牌、运行时路径、service.py 路径和 install_id 安全停止。完成后恢复
  原有主任务启用状态。不按端口、进程名或 PID 强制结束任何进程。

⑤ 取消开机自动启动
  禁用主任务，仅通过“service.py --stop”安全停止当前服务；成功后禁用后台防火墙规则。
  每日 02:00 备份任务保持原有状态，不会因取消开机启动而停用。以后可用①手动启动，
  或用③恢复开机启动。

⑥ 从备份恢复
  只在本安装受保护的“_程序文件\backups”中，选择序列最新、与当前 install_id
  一致且具有配对 sidecar 的数据库。工具会显示文件、序列和时间；只有准确输入
  RESTORE 才继续。确认后临时禁用主任务和备份任务，等待正在执行的备份自行结束，
  通过 service.py --stop 安全停服，再调用“restore.py --backup <绝对路径>
  --expected-install-id <当前 install_id>”。restore.py 会复核 sidecar、SHA-256、数据库内部元数据，
  并先保留恢复前快照；失败时尝试原子回滚。无论成功与否，都尝试恢复原有两个任务的
  启用状态；如服务原本运行，还会重新启动并复检。
  警告：恢复后，所选备份之后产生的业务变更不再保留。如不确定，请先联系维护人员。

固定运行约定
  - 端口固定为 TCP 8080。首次设置完成前只允许本机 127.0.0.1:8080 访问；设置完成并由
    服务安全重启后，才允许同一局域网访问。
  - 端口被未知程序占用时，V2 会停止并报告，不结束未知进程，也不改用随机端口。
  - V2 不枚举、不读取、不迁移也不删除任何 V1 目录或数据库。
  - 遇到故障请保留安装现场。data、backups 和 logs 受 DACL 保护，查看或导出日志
    需由维护人员使用管理员权限操作。
