# 会议室预约系统

单位局域网使用的轻量会议室预约系统，以及面向 Windows 10/11 的完整离线更新机制。

当前客户基线：V1.0.2-r1。当前开发候选：V1.0.3，尚未通过 Windows 普通用户
实机验收，不得正式外发。
V1.0.1 候选物保持冻结，作为修复基线；原 V1.0.2 单 BAT 也保持冻结，
只作为入口故障证据，不再发送给客户。

## V1.0.3 候选范围

- 日历增加日期直达；已预约时段可点击查看必要详情，备注不进入日历 DOM。
- “我的预约”待使用优先、历史默认收起，手机端使用卡片布局。
- 管理员手机端的正常局域网地址栏压缩为单行；地址变化警告仍完整显示。
- `SCHEMA_VERSION=1`、`MIGRATIONS=[]`，不修改数据库、依赖和冻结 runtime。
- V1.0.3 使用完整候选更新 ZIP：顶层零参数 BAT 只启动包内 Python，由 Python
  校验负载、定位安装并直接请求管理员权限；不再生成或调用旧带参数 RunAs 累计 BAT。
- 支持 V1.0.0、V1.0.1、干净 V1.0.2、r1 修复后状态、r1 未完成事务和旧累计残留；
  重复运行安全收敛，目标提交前失败时停在已验证的 V1.0.2 安全基线。

## V1.0.2-r1 修复更新

- 客户收到完整修复 ZIP 后解压，双击零参数
  `修复并更新到V1.0.2.bat`；入口不再通过带参数 RunAs 执行 BAT。
- 修复器使用随包冻结 Python 直接请求管理员权限，路径包含中文、空格、`(1)` 或 `&`
  时也不把 BAT 路径交给 `cmd /c` 二次解析。
- 当前真实 `data` 是唯一权威数据源。修复器先复制并校验 data，再把受管程序严格恢复
  到冻结 V1.0.1，随后覆盖 V1.0.2；数据库与服务检查只针对副本。
- V1.0.2 提交前失败会停在已验证的 V1.0.1；提交后绝不自动降级。旧
  `_升级回滚` 只保留为证据，不用于覆盖当前 data。
- 修复成功后由客户再双击原目录的 `① 启动系统.bat`，避免管理员更新进程猜测最终
  服务应以 SYSTEM 还是普通用户身份启动。

## V1.0.2 业务体验

- 局域网地址变化时，仅管理员看到持续提醒，可复制新地址通知同事；同事改用新地址后可能需要重新登录，原账号、会议室和预约数据不会变化。
- 多套安装时不按盘符或搜索顺序猜测；安装目录必须位于本机固定磁盘，不支持共享盘、U 盘、移动硬盘或网盘同步目录。

## 目录

- `02_开发工作区/源代码工作区`：Flask 应用、数据库迁移框架和业务测试。
- `02_开发工作区/升级包工具`：发布骨架、一键发布组装器、BAT 生成器、PowerShell 5.1 升级事务和测试。
- `02_开发工作区/发布暂存`：从唯一源码自动生成的版本化候选物，不作为源码维护。
- `02_开发工作区/Windows部署目录-V1.0.0`：旧版测试基线；版本库不跟踪 runtime 和数据，本机可保留冻结 runtime 用于验证。
- `02_开发工作区/Windows部署目录-V1.0.1-待实机验收`：冻结候选基线；版本库不跟踪 runtime 和数据，本机完整候选使用同一冻结 runtime。
- `02_开发工作区/升级机制实施计划.md`：升级、回滚和验收规则。
- `02_开发工作区/后续版本路线图-V1.0.4至V1.1.x.md`：修改预约、API、大屏、
  提醒、结构整理及 V1.1 产品转型的规划边界；不是当前候选范围或发布承诺。

## 测试

本地业务与迁移测试：

```bash
cd 02_开发工作区/源代码工作区
python -m unittest discover -s tests -v
```

升级包生成器测试：

```bash
cd 02_开发工作区/升级包工具
python -m unittest discover -s tests -v
```

GitHub Actions 保留原累计升级回归、V1.0.2-r1 的真实零参数 BAT 集成路径，并加入
V1.0.3 完整候选更新矩阵。
提交后由 Windows PowerShell 5.1 作业在临时安装目录验证：

- V1.0.0 直接升级到当前目标版本；
- V1.0.1 升级到当前目标版本；
- 用户、会议室、预约、会话密钥和数据库结构保留；
- 安装身份、局域网地址状态和计划任务归属不会与另一套安装混淆；
- 同一 BAT 重复运行安全退出；
- 两种旧版本起点的故障 Payload 都能恢复旧程序、旧版本文件和旧数据；
- 事务阶段中断后不会在提交前向局域网开放新版，也不会在提交后错误回滚新数据；
- 原运行/停止状态与计划任务启用状态正确恢复，成功快照及时清理。
- V1.0.3 从缺少 `版本.txt` 的 V1.0.0、V1.0.1、干净 V1.0.2 和 r1
  未完成状态进入同一正式更新事务；
- V1.0.3 的重复运行、目标失败回到 V1.0.2 安全基线及 data 全树不变。

本地自动化不能替代交互式 UAC、SmartScreen、杀毒软件/EDR、AppLocker、
真实开机计划任务、防火墙、VPN、DHCP、物理断电和另一台同事电脑访问。V1.0.3
只能生成候选版；普通用户 Windows 10/11 双击及局域网实机验收通过前不得写成
“正式发布通过”或对外发送。

## 安全

仓库忽略所有 `data`、`logs`、`backups`、runtime、本机虚拟环境、数据库、首次登录凭据、
正式交付归档和发布暂存。只追踪明确验证过的版本 BAT 与发布清单；不要把客户安装目录
直接复制到仓库。
