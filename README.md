# 会议室预约系统

单位局域网使用的轻量会议室预约系统，以及面向 Windows 10/11 的单文件累计升级机制。

当前正式版本：V1.0.2。V1.0.1 候选物保持冻结，作为升级与回滚基线。
V1.0.2 已通过自动化验证，并于 2026-07-26 由用户确认在现有客户环境升级成功。
这项实机结果用于本版本正式收口，不代表所有 Windows 10/11、安全策略和网络环境均已覆盖。

## V1.0.2 升级体验

- 用户只需保存当前操作并双击累计升级 BAT；升级器自动定位、备份、更新、检查并恢复原运行状态，不需要手工迁移数据库或修改配置。
- 双击后会显示管理员授权提示；入口异常会留在窗口中，并写入临时入口日志供网管排查。
- 升级有短暂停机；停机瞬间正在提交的页面可能需要在升级成功后刷新重试。
- 成功摘要会说明版本、数据保留结果、最终运行状态，以及局域网地址未变、已变化或暂时无法确认。
- 局域网地址变化时，仅管理员看到持续提醒，可复制新地址通知同事；同事改用新地址后可能需要重新登录，原账号、会议室和预约数据不会变化。
- 多套安装时不按盘符或搜索顺序猜测；安装目录必须位于本机固定磁盘，不支持共享盘、U 盘、移动硬盘或网盘同步目录。

## 目录

- `02_开发工作区/源代码工作区`：Flask 应用、数据库迁移框架和业务测试。
- `02_开发工作区/升级包工具`：发布骨架、一键发布组装器、BAT 生成器、PowerShell 5.1 升级事务和测试。
- `02_开发工作区/发布暂存`：从唯一源码自动生成的版本化候选物，不作为源码维护。
- `02_开发工作区/Windows部署目录-V1.0.0`：旧版测试基线；版本库不跟踪 runtime 和数据，本机可保留冻结 runtime 用于验证。
- `02_开发工作区/Windows部署目录-V1.0.1-待实机验收`：冻结候选基线；版本库不跟踪 runtime 和数据，本机完整候选使用同一冻结 runtime。
- `02_开发工作区/升级机制实施计划.md`：升级、回滚和验收规则。

## 测试

本地业务与迁移测试：

```bash
cd 02_开发工作区/源代码工作区
python -m unittest discover -s tests -v
```

升级包生成器测试：

```bash
cd 02_开发工作区/升级包工具
python -m unittest discover -s tests -v
```

GitHub Actions 的 Windows PowerShell 5.1 作业会从唯一源码重新组装发布负载，核对精确候选
BAT，并在临时安装目录验证：

- V1.0.0 直接升级到当前目标版本；
- V1.0.1 升级到当前目标版本；
- 用户、会议室、预约、会话密钥和数据库结构保留；
- 安装身份、局域网地址状态和计划任务归属不会与另一套安装混淆；
- 同一 BAT 重复运行安全退出；
- 两种旧版本起点的故障 Payload 都能恢复旧程序、旧版本文件和旧数据；
- 事务阶段中断后不会在提交前向局域网开放新版，也不会在提交后错误回滚新数据；
- 原运行/停止状态与计划任务启用状态正确恢复，成功快照及时清理。

已有客户环境已完成实际升级。交互式 UAC、SmartScreen、杀毒软件/EDR、AppLocker、
真实开机计划任务、防火墙、VPN、DHCP、物理断电和另一台同事电脑访问仍属于环境相关
验收项；部署到新的 Windows 10/11 环境时应继续逐项核对。

## 安全

仓库忽略所有 `data`、`logs`、`backups`、runtime、本机虚拟环境、数据库、首次登录凭据、
正式交付归档和发布暂存。只追踪明确验证过的版本 BAT 与发布清单；不要把客户安装目录
直接复制到仓库。
